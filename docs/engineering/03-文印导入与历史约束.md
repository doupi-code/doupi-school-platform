# 文印导入与历史约束

本文保留微信文印导入、扫描直传和备案配置的有效维护约束。历史验证结果只说明当时的验证范围，不代表当前生产环境已经验收。本次文档整理未访问线上、未运行升级脚本、未重新验证设备。

## 1. 微信文印导入的业务约束

- 导入用于整理候选和预填登记，须人工逐条核对后保存。解析、文件选择、预览和编辑不产生出库；保存沿用既有登记与库存事务及权限。
- 缺附件、附件过期、上传失败、只有材料或只有要求，均保留候选供人工补全。未知份数、原稿页数留空；日期没有证据时不猜测。
- 微信昵称不直接等同教师档案。选择教师后，可应用到本次同一发送人的候选；关联有歧义时须对照原文确认。
- 原文面板展示当前候选所在日期的全部聊天，突出关联材料与要求，并可定位当前记录。日期未知时展示本次取得的聊天。
- 文件名唯一匹配时才能自动关联附件；同名歧义交人工选择。PDF、Word 分析结果可补充空缺页数；Excel 工作表数不视为打印页数。
- 未明确纸型时默认 8K，原稿为单页 A4 时默认 16K；按既有 1.5 倍面积阈值换算，始终从原稿基数计算。明确页码范围优先于附件完整页数。
- 聊天明确要求及手动修改优先。手动修改页数后，后续换纸或文件分析不得覆盖；试卷、答案拆分只能依据当前候选关联的消息。
- 保存成功才进入下一条；保存失败保留输入和当前候选。候选切换保留本会话草稿，导入与保存互斥，异步文件处理不得覆盖其他候选。
- 关闭浏览器后的会话恢复不属于原预填重构已完成的范围，不能承诺草稿长期留存。

### 同名提醒与来源防重的区别

历史同名文件只提示疑似重复，不自动跳过。带有明确会话、消息来源的登记须执行来源防重；已登记材料再次办理必须显式选择重印。两者不能互相替代，也不能用本地批次或任务标识承担持久化去重。

## 2. 导出目录导入与账号筛选

- 默认隐藏已确认的公众号、企业微信账号；未知类型保留显示，不根据联系人名称猜测账号类型。
- 被账号类型筛选隐藏的已勾选会话保留选择，但不参与本次识别。“只看已勾选”只改变展示。
- 会话列表默认每页 50 条，可切换 20、50、100 条。
- 旧 TraceMemo 导出清单可能将所有会话写为 `user`。可在导出目录提供 `联系人分类.json`，按会话 ID 补齐类型；缺失或无法读取时，未确认账号仍显示。
- 补齐分类使用 `scripts/export-wechat-account-types.ps1`。前置条件为 PowerShell 7、TraceMemo 已连接对应数据库、配置本机 `TRACEMEMO_API_TOKEN` 环境变量。脚本兼容旧凭证变量，只写会话 ID 和账号类型，不修改聊天、不保存凭证。生成分类后须重新选择导出文件夹。
- `crypto.randomUUID` 不可用时存在兼容标识生成方式；这些标识只隔离本地界面任务，不用于鉴权或持久化来源去重。

## 3. 部署与数据前置条件

### 微信来源登记

- 核对并按部署环境情况执行 `doupi-server/sql/upgrade_print_record_extra_paper_and_wechat_source.sql`，保留额外用纸和消息来源字段。
- 部署来源并发防重前，还须执行 `doupi-server/sql/upgrade_print_source_registration_lock.sql`。锁行供数据库事务串行处理同一来源，事务提交或回滚后释放事务锁；导入期间不得清理来源锁表中的行。
- “预填重构未修改数据库结构”是当次变更边界，不能据此省略后续来源登记所需升级。本次文档整理未确认任何环境是否已经执行上述脚本。

### 网站备案配置

- 官网及管理端页脚使用同一份管理员维护的 ICP、公安备案号及查询链接；链接只接受 HTTP/HTTPS，保存和预览均须阻止危险地址。
- `doupi-server/sql/upgrade_cms_site_filings.sql` 仅补缺失字段，保留既有管理员配置，可重复执行；适用数据库版本以脚本声明为准。
- 执行后在后台页脚配置保存一次，以清除相关 CMS 缓存；未保存时旧缓存最长保留 30 分钟。两端仍需兼容缺失的新字段。
- 本次文档整理未执行真实数据库升级，不应将脚本存在等同于生产已经更新。

## 4. 验证范围与待复核项

### 微信剪贴板与导入

- 浏览器只能处理微信实际提供的文字、HTML 和文件。微信没有提供的过期消息无法恢复，此时保留已取得的文件候选供人工填写。
- 标准剪贴板自动测试不能代替用户电脑上真实微信复制路径的验收。
- 导入和登记弹窗提供解析调试；最近 10 次记录仅保存在页面内存，刷新即消失，可手动清空。原始 HTML 作为文本展示，不执行。调试记录可能包含聊天正文和文件信息，不应直接复制到公开问题单。
- 排查时分别比较原始粘贴、补读结果、实际提交文字、后端消息与候选，避免将文字缺失、解析问题和附件匹配混为一谈。
- 历史验证包含前端单测、模拟接口浏览器交互及 H2、Spring 事务、生产 MyBatis 来源锁 SQL 测试；这些不能等同于生产 MySQL 的完整链路验证，也没有证明真实微信私有剪贴板格式已验收。

### 未知页数与单双面：历史待复核

原业务说明要求未知页数不推断单双面；备案变更记录曾报告既有印刷规则回归失败：空输入的单双面实际默认为单面，测试期望为空。本次整理时相关规则与测试仍存在这一差异，但未重新执行测试。

该项保留为未关闭的历史待复核事项。复核前不得将“未知页数不推断单双面”写成已验证现状，也不得把既有回归描述为全部通过。

### 备案验证的边界

历史记录中的页面验证使用本地服务和模拟接口，涉及旧字段兼容、非法链接、预览、保存重载、两端一致、图标及窄屏展示；未连接真实数据库，升级 SQL 未执行。构建或模拟验证不能替代真实配置保存、数据库升级与线上缓存核对。

## 5. 扫描直传的暂停决定与恢复条件

完整证据保留于[2026-10-16 扫描直传暂停记录](decisions/2026-10-16-扫描直传暂停记录.md)。该档案为历史、暂停记录，未重新线上复验。

### 已知结论

- 用户在链路未通过后要求撤销本次新增设施、保留详细记录并暂停；扫描收件箱没有上线，未迁移历史附件。
- 当时电脑经公网被动 FTP 上传成功；理光设备可以认证并进入接收目录，但实际使用主动 FTP，声明内网数据连接地址。
- 初始配置拒绝主动模式；启用后仍被地址校验拒绝。没有成功上传的扫描 PDF，没有实扫页数验收结果。
- 本次新增 FTP 服务、专用账号、接收目录、网络规则及设备通讯簿目的地已按当时记录撤销；本次整理未重新核查线上状态。
- 不能把碳粉、日志或维修告警当成已确认根因；也不能断言设备绝对不支持被动模式，或认为关闭地址校验即可解决公网到内网的路由问题。
- 历史 IP、端口、软件版本、设备时钟及防火墙数量仅为当时快照，恢复前必须重新核实，不应写入产品默认配置。

### 恢复前的业务与维护约束

- 先取得新的恢复决定，再验证链路；至少三次真实多页扫描完整抵达，确认格式、页数、重名处理、中断与恢复，之后再开展收件箱业务。
- 接收文件须私有归档，具备完整传输确认、格式和大小检查、异常记录与重启恢复能力；不能只以短时间文件大小不变判断完成，接收目录不得作为网站公开附件目录。
- 扫描单双面不等于印刷单双面。教师、份数和印刷要求须人工确认；选择或解析文件不扣库存。
- 扫描登记与附件关联须整体成功或整体回滚，来源防重和显式重印同样适用。原暂停方案沿用了当时“保存登记扣纸”的口径；若今后恢复，须按[文印产品规则](../product/features/02-文印管理.md)区分计划、实际领纸与完工核销，不在登记或预览时扣库存，各次真实收发单独保持完整一致。
- 历史提出的设备被动模式、网络互联和校内中转只是待选方向，不是已部署能力。恢复时应重新核实现场条件，不沿用旧实施授权。

## 6. 历史附件访问风险：未关闭

2026-10-16 记录指出，历史文印附件通过公开静态路径可能被匿名访问，当时未修复。该问题须独立于扫描直传暂停状态保留；本次文档整理未重新线上验证，不应声称当前生产风险已经消除。

恢复相关业务前，应复核私有上传、业务身份校验下载、旧静态地址、通用下载及哈希秒传等入口，避免只保护新文件而遗留旧地址或旁路。历史迁移须先盘点备份，再复制校验、切换引用、关闭旧公开副本，同时保留头像等应公开的资源。

历史诊断与回滚证据按档案保留，不为清理文档而删除其他业务审计记录。密码、密钥、凭证文件与设备恢复备份不得进入项目仓库；恢复部署前还须核对现有环境改动、空间监控和回滚方案。
