## 3. 跨端主流程

以下文印、物资、通知流程为P1接入App后的跨端目标。本期P0由申请人通过管理后台授权的个人办事入口提交、补充、查询及确认；线下需求可由行政代录，实际领取由指定领取人或明确授权的代领人确认，代录不自动替代签收。访校流程为现有Web、小程序与后台的保留业务。

- **文印**：教职工在App提交原稿与要求 → 行政后台受理和核对 → 指定负责人在后台或App审核 → 文印岗位接单、领纸和印制 → App通知领取并由领取人确认 → 后台核对耗材与归档，各端显示同一进度。
- **物资**：App申请物品或套装 → 后台受理及按规则审核 → 仓库按实际数量发放 → App确认实收，欠发部分继续显示 → 从原领用清单发起归还 → 仓库验收后更新各端应还数量。
- **访校**：家长从Web或小程序提交 → 招生后台确认并安排接待 → 小程序展示预约凭证 → 授权工作人员在小程序或后台核销 → 家长可查询本人状态，招生人员保留沟通备注。
- **通知**：行政后台选择接收范围发布 → App展示本人通知 → 接收人确认阅读 → 后台核查未确认人员；阅读不替代关联事项办理。
- **监护激活（P0新）**：后台正式学生建档 → 班主任收集监护姓名手机号关系 → 校方核实关联 → 小程序验证真实本人手机号后激活；漏名先校方补录再发定向限时一次邀请，异常号码和换微信校方核实。
- **成绩（P0新）**：教务后台Excel导入并处理异常 → 按考试＋班级发布 → 小程序当前有效家长查询分数历史 → 撤回即不可见 → 更正以新版本发布；转班不改历史班级。
- **家校通知（P0新）**：后台发布学生范围快照 → 当前有效家长小程序查看 → 各家长分别阅读／确认 → 后台主统计按每学生至少一位当前有效监护人确认，转班不重算学生快照。
- **开放日（P0新）**：后台配置独立活动和校区场次 → 家长小程序选适用孩子及实名人员，有名额即成功 → 符合条件可取消释放，改期P0取消后重约且告知风险 → 授权工作人员后台或小程序按实际人员分批入校 → 当面送物 → 工作人员登记、家长自报或核实补录可选离校，保留来源。

## 4. 版本口径

- 原行政主线及Web、小程序既有招生游园和公开内容保留；新增P0正式学生、监护关系、分数历史、家校通知及在校开放日送物，均已确认待开发，不声称既有能力。
- 截至2026-11-05，App核心申请、待办、审批、领取与归还确认仍按P1迭代；P0后台完成内部行政闭环，小程序与后台共同交付新家校服务。
- App核心移动动作的优先级与“完整移动办公”区分：批量核销、复杂报表导出、全量库存盘点、门户编辑器、全部桌面功能搬迁不自动纳入核心闭环。
- 现有小程序员工入口与独立App中的演示内容按动作验收，不能以页面数认定完成度。
- P1新增开放日候补与正式改期、成绩疑问与同口径趋势；P2学生请假、考勤和作业。开放日不包含物品代收物流签收、硬件门禁人脸或强制出校。

## 5. 全端验收要求

- 同一事项在后台和App的申请人、数量、状态、处理意见、待领取与应还数量一致。
- Web与小程序对同一预约使用同一确认规则和到校事实；重复核销不能增加到校人数。
- 未授权的家长、教职工不能通过换端查看他人材料；内部角色不能因使用移动端绕过审批或独立复核。
- 一个端发起的实际收发在其他端只反映同一次业务，不重复扣库存；失败、待确认和成功分别表达。
- 各端退出后再次进入能够查询已提交事项；未保存草稿是否可恢复须明确，不默认承诺长期保存。
- 成绩仅正式发布且关系有效时可见，撤回不可见，更正保留版本；通知快照与逐家长回执在后台小程序一致。
- 开放日按实名访客人数占位，同孩同活动唯一有效单，两家长竞争仅一成功；另一监护人仅知本人孩子已约，不见订单其他孩子和访客，同行无学生成绩权。
- 入校按实际人员分批且重复不重复计人；离校来源区分且非强制，离校不释放本场总容量，结束不自动标离校，统计称“已入校未登记离校人数”，不称实时在校人数。
- 开放日一活动单校区单日期，可含多个到校时段；跨校区或跨日另建活动。同家长同活动一有效单，多孩同一时段，原单保留原时段和完全相同实名人员可追加适用关联孩子而不增加占位。毕业／离校停止家长资料访问，历史内部保留；学生直接访问留P2。
