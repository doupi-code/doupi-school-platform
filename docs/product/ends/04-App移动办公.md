# App移动办公产品说明

更新日期：2026-11-04。状态：完整产品规划补充；已确认App仍按P1迭代，现有工程混有演示内容，不计为完整办公交付。

## 1. 用户与目标

面向教职工、班主任、行政经办人员和负责人，承载离开办公桌后仍需完成的申请、补充、审核、接单、领取与归还确认。App与后台办理同一事项，不能形成独立审批、独立库存或仅本机可见的结果。

## 2. 页面与导航

- **工作台**：快捷申请、待我处理、办理中、待领取、待归还和重要通知。
- **办事**：文印申请、物资申请、我的申请、已办事项与常用办事指引。
- **待办**：待审核、待补充、待接单、待领取确认、待归还验收及异常反馈，按岗位显示。
- **消息**：业务提醒、内部通知、重要通知阅读确认；点击进入具体事项。
- **我的**：本人资料、岗位范围、负责班级、代办授权及退出。

文印工作人员可见印制队列和交接动作；仓库人员可见待发放、待签收和退还验收；负责人可见待审批和盘点复核。复杂批量台账和基础档案编辑不搬入普通用户首页。

## 3. 功能清单

- **移动文印申请与补充**  
  **适用角色：**教职工、班主任。  
  **操作流程：**上传或选择原稿 → 填写用途、份数、纸型、单双面、期望时间和领取人 → 核对提交 → 根据退回意见补充。  
  **业务价值：**使需求从发起时即进入统一记录。
- **移动物资申请与归还**  
  **适用角色：**教职工、班主任。  
  **操作流程：**选择单品或套装 → 填写数量与用途 → 提交并查询批准和待补数量 → 从原领用清单发起归还。  
  **业务价值：**申请人清楚看到实领、欠发和应还情况。
- **岗位审批与接单**  
  **适用角色：**负责人、行政及执行岗位。  
  **操作流程：**查看本人待办和完整要求 → 通过、拒绝、退回或接单 → 记录意见及办理期限 → 查询已处理结果。  
  **业务价值：**减少因人员不在办公室造成的等待。
- **领取确认与现场凭证**  
  **适用角色：**领取人、文印人员、仓库人员。  
  **操作流程：**收到待领取通知 → 核对实际品类数量 → 确认或反馈差异 → 必要时补充照片和说明；归还由仓库验收后完成。  
  **业务价值：**区分经办完成、实物交接和领取确认。
- **真实消息与进度查询**  
  **适用角色：**全部App用户。  
  **操作流程：**查看本人事项和消息 → 进入关联详情 → 处理当前动作 → 再次查询正式结果。  
  **业务价值：**让申请人主动掌握进度，减少追问。

## 4. 现状与目标差距

现有App有登录、工作台、消息及文印、物资、招生等页面，但部分列表、待办、状态变化和成功提示为演示，不能据此认定移动办理已经贯通。

目标要求真实身份与授权、正式事项查询、完整操作结果、失败恢复及与后台一致的业务状态。拍照或选择文件只是补充资料，不代表申请已保存、审批已通过或库存已变更。

## 5. 核心操作流程

1. 用户完成登录，进入其岗位范围的工作台。
2. 选择发起申请或本人待办，查看必要资料。
3. 核对原稿、物品、数量、用途及期望时间后提交动作。
4. 明确显示成功、失败或结果待确认；失败保留可恢复输入，结果不明时先查询，避免重复办理。
5. 后台受理或其他岗位处理后，App展示新的当前环节与责任人。
6. 指定领取人完成实际领取确认；需归还物资继续保留应还清单。
7. 用户再次进入仍能查询正式记录、意见、交付及归还状态。

## 6. 规则与验收

- 权限与后台一致；App不得自行选择负责人身份、代替无授权人员审批或批准本人盘点。
- 申请、接单、领取确认和完工核销不能重复扣同一次库存；跨端重复操作只能形成一次有效业务。
- 交付数量与原事项对应，部分发放继续保留待补，损坏归还不增加可用库存。
- 正文、原稿和凭证只向有权人员展示；下载、分享和预览不能绕过相同业务范围。
- 无消息时显示空状态，办理失败不能显示演示成功；网络恢复后以正式记录为准。
- 核心移动闭环与复杂桌面操作分别验收；批量盘点、全量导出、门户编辑器和所有后台功能搬迁不自动计入核心交付。

## 7. 版本安排

核心闭环包括申请、待办、补充、审核、接单、领取与归还确认；本次完整定义这些需求。2026-11-04已确认App功能仍按P1迭代，P0先由管理后台授权的个人事项与岗位入口完成内部业务。采购、报修、公共资源预约等扩展仍按P1，完整资产、人事及跨校区协同仍按P2。
