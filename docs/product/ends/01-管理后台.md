# 管理后台产品说明

更新日期：2026-11-05。状态：P0集中办理端规划，保留已有行政登记基础；正式学生、监护关系、成绩、家校通知和在校开放日均为已确认P0首批待开发，完整流程须逐项验收。

## 1. 用户与目标

面向行政、教务、文印、仓库、招生、宣传、班主任、家校岗位及负责人，承担批量受理、复杂表单维护、执行核查、异常处置和归档对账。保留行政三条主线，新增在校服务的正式建档、核实与发布中心；后台与移动端处理同一事实，不另建独立申请清单。

## 2. 页面与导航

- **工作台**：待我处理、待分派、超期、缺货、待领取、待核销及重要通知。
- **协同事项**：我的申请、受理队列、审批队列、办理中、待确认、已办及取消记录。
- **文印管理**：需求受理、原文与原稿核对、印制队列、领纸退纸、实耗核销、交付清单与异常重印。
- **物资领退**：领用申请、套装发放、缺货待补、待签收、归还验收与异常责任。
- **库存管理**：物资、供应商、到货验收、收发流水、低库存、盘点及独立复核。
- **通知与台账**：内部通知、接收范围、阅读确认、业务明细与授权导出。
- **招生接待**：既有预约台账、规则设置、接待安排、到校核销与备注。
- **门户维护**：公开内容、学校基础资料、草稿与发布，内容审核为P1。
- **基础管理**：组织人员、班级、角色权限、常用套装与办事规则。
- **学生档案（P0新）**：校区、全校唯一学号、姓名、班级、入学年度、在读／毕业／离校状态与转班历史；现有后台无正式学生，本项不可由预约姓名或光荣榜替代。
- **监护关系（P0新）**：班主任收集姓名手机号关系、校方核实关联、激活与失效、漏名补录及定向限时一次邀请、异常手机号与换微信核实记录。
- **考试成绩（P0新）**：考试班级与科目满分、Excel导入、学生匹配、异常处理、总分检查、按考试＋班级发布、撤回、更正版本及授权历史。
- **家校通知（P0新）**：适用学生范围快照、内容发布、逐家长阅读／主动确认明细、按学生至少一位当前有效监护人确认统计。
- **家校开放日（P0新）**：独立于招生的活动与校区场次、报名和取消窗口、人数容量及每单上限、适用学生和交接区域、订单核查、停办通知、实际人员入校及可选离校台账。

导航按岗位展示；后台可见某项菜单不等于拥有其全部操作和数据范围。

## 3. 功能清单

- **后台集中受理**  
  **适用角色：**行政／教务经办人。  
  **操作流程：**查看后台个人办事入口提交或线下代录事项 → 核对资料 → 退回补充或按规则分派；P1接入App后沿用同一队列。  
  **业务价值：**统一处理来源，减少漏单和重复登记。
- **执行、盘点与异常核查**  
  **适用角色：**文印、仓库、负责人。  
  **操作流程：**打开岗位队列 → 登记真实执行与收发 → 核查差异 → 复核或交付。  
  **业务价值：**承载需要完整资料对照和多项明细核对的操作。
- **档案、规则及台账管理**  
  **适用角色：**授权管理员、行政人员及负责人。  
  **操作流程：**维护统一基础资料和责任岗位 → 按授权查询汇总 → 核对来源明细并归档。  
  **业务价值：**为四端提供一致的业务基础与核查依据。
- **正式学生与监护关系核实（P0待开发）**  
  **适用角色：**教务、班主任、校方核实人员。  
  **操作流程：**正式建档与学号检查 → 班主任提交监护姓名手机号关系 → 校方核实关联 → 家长小程序真实本人手机号验证激活 → 校方处理补录、失效或异常。  
  **业务价值：**支持一人多孩、一孩多监护人，微信身份与家长资格、员工权限分别处理，手输手机号不能取得成绩权限。
- **Excel分数处理与正式发布（P0待开发）**  
  **适用角色：**教务、授权成绩处理和发布人员。  
  **操作流程：**确定考试班级、满分及计分规则 → Excel导入并处理异常 → 按考试＋班级发布 → 必要时撤回并更正新版本。  
  **业务价值：**零分、缺考、免考、未录入分开，应计科目齐全才有总分，未处理异常不能发布，撤回不可见，学校留存版本责任，无排名等级评语。
- **家校通知与学生确认核查（P0待开发）**  
  **适用角色：**班主任、授权家校发布人员。  
  **操作流程：**选择学生快照发布 → 当前有效家长小程序阅读和确认 → 后台按学生核查至少一位当前有效监护人已确认 → 查看逐家长明细跟进。  
  **业务价值：**不将家长人数代替学生人数、不将打开通知代替主动确认，转班不重算快照，失效关系不可继续访问。
- **开放日活动、人数与现场记录（P0待开发）**  
  **适用角色：**活动管理人员、授权现场工作人员。  
  **操作流程：**配置场次、容量、上限、适用学生及交接区域 → 核查合单与同孩唯一预约 → 处理停办通知和凭证失效 → 按实际人员分批入校 → 区分来源记录可选离校 → 查询台账。  
  **业务价值：**按实名人员人数接待，重复不重复计人，离校不释放总容量，统计仅称“已入校未登记离校人数”。

## 4. 与其他端的协作

本期接收Web和小程序的入学前招生游园，维护门户公开内容，内部行政事项通过后台授权入口办理。新增P0由后台维护正式学生、核实关系、处理发布分数和家校通知、配置开放日；小程序家长以当前有效监护关系查看孩子分数历史、确认通知、预约送物，授权现场人员可在小程序或后台逐人登记。学生本人访问留P2；毕业／离校停止家长资料访问、历史内部保留，Web不新增私密成绩入口。P1接入App后复用内部同事项授权与进度。

## 5. 验收与边界

本期须能完成行政三条主线及新在校服务，按[验收标准](../04-验收标准.md)核查。复杂维护、Excel处理与授权全量导出在后台；配置权限不自动赋予成绩查看或发布权限，对外发布不暴露内部材料。具体要求见[在校服务](../features/07-学生与家长在校服务.md)、[开放日送物](../features/08-家校开放日送物预约.md)及原行政[功能文档](../../README.md)。

开放日有名额即成功，后台不沿用招生待确认规则；无人入校且截止前取消释放人数，P0改期取消重约并告知风险。停办失效凭证且保留现场历史；人员可分批入校，离校非强制、来源区分，无记录不等于仍在校，活动结束不自动已离校。物品代收物流签收、硬件门禁人脸和强制出校不包含；候补正式改期、成绩疑问趋势为P1，学生请假考勤作业为P2。
