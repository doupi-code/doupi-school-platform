# 微信小程序产品说明

更新日期：2026-11-05。状态：既有入学前招生预约与接待基础继续保留；入学后学生家长服务和家校开放日已确认纳入P0首批待开发，不能以现有页面或演示数据认定已交付。App仍为P1。

## 1. 用户与目标

小程序承载从入学前到入学后的微信内必要服务：入学前了解学校、预约游园和查询凭证；入学后以学校正式学生档案为基础，当前有效家长查看关联孩子的已发布分数与历史，接收家校通知并预约学校指定开放日入校当面送物。学校授权人员在独立员工入口办理招生接待和开放日现场登记。在校服务“本人”指登录家长及其有效关联孩子，学生直接访问留P2。

微信身份、家长资格与学校员工权限分别核实，不因能登录、知道某个手机号、持有邀请或是同行访客而获得学生资料。教职工文印物资等全量移动办公仍由P1 App承载，小程序不复制完整行政后台。

## 2. 页面与导航

### 2.1 公开／入学前入口

- 首页、学校与校区介绍、招生指引、公开资讯和常见问题。
- 招生游园预约、我的游园预约、详情、确认状态、有效到校凭证、取消与联系学校。
- 本人资料、隐私与使用说明；未取得在校资格者仍可使用适用公开服务，不能进入私密查分。

### 2.2 入学后家长入口（P0新增待开发）

- **在校服务首页**：当前关联孩子、已发布考试、待确认通知、适用开放日指引。
- **关系激活与我的孩子**：真实本人手机号验证、校方已核实关系匹配、一人多孩子切换、关系状态与联系学校；漏名先校方补录，再使用定向、限时、一次有效邀请。
- **分数与历史**：按关联孩子、考试或学期查询各科满分、分数及特殊状态、符合条件的总分、发布版本和历史，无排名等级评语。
- **家校通知**：适用学生通知列表、详情、已读状态、家长主动确认及孩子切换；同一家长多孩分别核查。
- **家校开放日**：适用活动及校区场次、报名与取消规则、人数余量、适用孩子、实名到访人员、同场多孩合单、提交结果、本人订单与凭证、取消、可选离校自报。

### 2.3 已核实员工入口

- **招生工作台**：本人接待安排、待确认或待到校事项；预约详情、必要联系方式、核销与沟通备注。
- **开放日现场入口（P0新增待开发）**：授权活动／校区名单、有效凭证核验、实名人员核对、分批入校、逐人可选离校与来源记录。
- **我的岗位**：校方核实的员工身份、职责与生效范围。家长资格不赋予现场权限，员工身份不赋予查看全部学生成绩的权限。

现有招生主管、邀请归属和管理页面按真实动作核验；排班、完整回访、排名绩效不因页面存在自动计入本期。

## 3. 功能清单

- **微信内招生游园预约与本人查单（保留与统一）**  
  **适用角色：**入学前家长、学生、访客。  
  **操作流程：**选择可预约日期时段 → 提交必要资料 → 查询确认安排、取消结果与有效凭证。  
  **业务价值：**降低预约和重复查询成本，与Web及后台保持同一招生事实。
- **招生接待移动办理（保留与完善）**  
  **适用角色：**已核实且获授权的招生工作人员。  
  **操作流程：**进入员工工作台 → 查看授权接待清单 → 核验到校凭证 → 记录真实结果与沟通备注。  
  **业务价值：**支持现场接待，重复核销不重复计到校，失败不显示成功。
- **正式关系激活与家长关联孩子切换（P0待开发）**  
  **适用角色：**家长、校方核实人员。  
  **操作流程：**后台正式学生建档 → 班主任收集监护姓名手机号关系 → 校方核实 → 家长验证真实本人手机号后激活 → 切换有效关联孩子。  
  **业务价值：**支持一人多孩、一孩多监护人；手输手机号、微信昵称、招生预约姓名或光荣榜均不能授予查分权。漏名由校方补录后发定向限时一次邀请，异常号码、换号与换微信由校方核实处理。
- **已发布分数与历史（P0待开发）**  
  **适用角色：**当前有效监护人。  
  **操作流程：**选择家长关联孩子 → 选择考试 → 查询教务后台Excel处理后按考试＋班级发布的各科满分、分数及历史。  
  **业务价值：**零分、缺考、免考、未录入分开；应计科目齐全才有总分，异常未处理不能发布，撤回不可见，更正显示新版本，无排名等级评语。成绩导入、异常处理和发布均在后台。
- **学生维度家校通知与主动确认（P0待开发）**  
  **适用角色：**当前有效监护人、班主任。  
  **操作流程：**按发布时学生范围快照获取家长关联孩子通知 → 每位家长分别阅读与主动确认 → 后台按学生核查至少一位当前有效监护人确认。  
  **业务价值：**不将已读当确认、不将一家长确认当全部家长已读；转班不重算快照，失效关系停止访问，回执历史保留。
- **开放日送物预约、凭证与取消（P0待开发）**  
  **适用角色：**当前有效监护人。  
  **操作流程：**查看学校指定校区日期时段、报名起止、取消截止、人数容量、每单上限、适用学生与区域 → 选孩子及实名到访人员 → 有名额即成功 → 查询凭证 → 无人入校且截止前可取消释放。  
  **业务价值：**同家长同场同校区多孩合一单，按实名访客人数占位，同孩同活动仅一有效单，两家长同时提交仅一成功；其他监护人只知本人孩子已约，不泄露同单其他孩子和访客。P0改期为取消后重约，提前提示原名额不保留和目标场次满额风险。
- **开放日人员现场记录（P0待开发）**  
  **适用角色：**授权现场工作人员、预约家长。  
  **操作流程：**工作人员核对有效订单与实际人员 → 可分批登记入校 → 家长入校当面送物 → 工作人员登记／家长自报／校方核实补录可选离校，分别记录来源。  
  **业务价值：**重复登记不重复计人，同行不获得学籍或成绩权；离校非强制、不释放总接待容量，无记录不等于仍在校，结束不自动已离校，统计称“已入校未登记离校人数”。停办通知失效凭证并保留历史。

## 4. 跨端主流程

- **入学前游园**：Web或小程序提交招生预约 → 后台招生办确认分配 → 小程序显示确认安排及凭证 → 授权员工现场核销 → 后台与家长查询反映同一到校事实。
- **入学后激活**：后台建立最小正式学生档案和转班历史 → 班主任提交监护资料 → 校方核实关联 → 小程序真实本人手机号验证后激活 → 一人多孩切换；漏名补录和异常处理回到校方核实。
- **分数**：后台教务Excel导入处理异常 → 按考试＋班级发布 → 小程序当前有效家长查询分数历史 → 撤回即不可见 → 更正新版本；未处理异常不能发布。
- **家校通知**：后台发布适用学生快照 → 小程序按当前有效关系展示 → 每家长分别阅读确认 → 后台按学生至少一位当前有效监护人确认核查。
- **在校开放日**：后台配置独立活动场次 → 家长小程序合单选孩子与实名人员，校验资格防重容量后有名额即成功 → 凭证到校，授权员工按实际人员分批入校 → 当面送物 → 可选离校记录保留来源；取消、停办与凭证失效跨端一致。

## 5. 业务规则、验收与边界

- 正式学生档案必须包含校区、全校唯一学号、姓名、班级、入学年度、在读／毕业／离校状态和转班历史。现有后台无正式学生，本次新增不能用预约姓名、光荣榜或教师班级替代。
- 微信身份、家长资格和员工权限独立，P0无学生本人登录与查分入口。小程序不接受手输手机号即取得成绩；邀请定向、限时、一次有效，转发、过期、重复使用与对象不符不生效。
- 分数仅正式发布且监护关系当前有效时家长可见关联孩子资料，未发布和已撤回均不可见；毕业／离校停止家长资料访问并内部保留历史，转班不重写历史考试班级。成绩内容限定分数、满分、符合条件总分和历史，无排名、等级、评语。
- 家校通知发布学生范围快照与当前有效监护关系分别判断；每位家长阅读和确认分开，一家长多孩按学生分别记录，主统计学生至少一位当前有效监护人主动确认。失效关系旧回执保留历史，不代替现关联确认。
- 开放日一活动对应单校区单日期，可含多个时段，跨校区或跨日另建活动；同家长同活动一有效单，多孩共用同一时段。原单保留原时段及完全相同实名人员名单可追加适用有效关联孩子，不增加人数占位；更换时段和访客按P0取消重约规则处理，名额不保证。
- 开放日独立于招生，不等待招生人工确认；按实名到访人员而非孩子数占位，同孩同活动唯一有效单。其他监护人仅获知本人孩子已约，不能取得他人订单其他孩子和访客资料。
- 已有人入校或超过取消截止不能按未入校规则自助取消；停办通知并失效凭证，历史不删；入校可分批且不重复计人，离校可选且来源区分，结束不自动离校，离校不释放本场总容量。
- 公开内容继续与Web使用同一正式发布资料；在校私密成绩、家校通知及开放日家长事务不扩展到Web。小程序不承载教职工文印物资完整移动办公，App仍P1。
- P1为招生回访排班、开放日候补和正式改期、成绩疑问及同口径趋势；P2为学生本人直接访问、学生请假考勤作业。物品代收物流签收、硬件门禁人脸、强制出校和实时在校人数均不含。
- 验收按[统一标准](../04-验收标准.md)、[在校服务](../features/07-学生与家长在校服务.md)和[开放日送物](../features/08-家校开放日送物预约.md)逐项完成，真实结果可再次查询，空状态、失败与成功分开，演示数据不作为证据。
