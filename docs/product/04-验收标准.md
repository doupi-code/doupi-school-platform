# 本期验收标准

更新日期：2026-11-05。状态：验收计划，当前无已通过结论；已确认学生家长在校服务和家校开放日为P0首批待开发，App仍为P1。文档整理不表示功能已经交付。

## 1. 验收范围与前置条件

本期验收文印、物资领退、库存三条行政主线及其角色权限、工作台、固定审批、通知、台账，并新增最小正式学生档案、监护关联、家长关联孩子分数历史、家校通知和指定开放日送物。已有入学前招生游园和门户维护检查保留情况，P1新增跟进、内容审核、App、开放日候补正式改期和成绩疑问趋势不计入本期完成要求。

验收前应由学校确认审核与替补岗位、免审批及超量条件、办理期限、物资换算和归还标准、期初库存与未结事项，并准备正式学生与监护名单、身份核实方式、试运行考试科目满分及计分规则、通知适用学生和开放日场次参数。所有验收样例须标明为示例，避免与真实业务混淆。

## 2. 关键业务验收清单

### 2.1 角色权限与协同

- **AC-01 授权范围**：教职工、经办人和负责人分别使用其岗位身份，验证查询、原稿查看、领取确认和导出均在授权范围内；关联[角色与权限](02-角色与权限.md)。
- **AC-02 真实工作台**：发起一项需审批事项，审核人收到对应待办；审批后进入指定经办人待办。无事项和未取得结果时不展示虚构业务；关联 COL 模块。
- **AC-03 代录与补充**：行政代录保留原申请人，材料不足可退回并补齐，原意见保留；代录不能自动代替审核或领取确认。
- **AC-04 固定审批与交接**：免审批及需审批两类事项按各自规则办理；缺岗不跳过必要审批；交接后新经办人可继续处理且责任记录完整。

### 2.2 文印

- **AC-05 预填人工确认**：导入聊天含同名附件、未知页数或不明确教师时，保留候选并提示核对；未经确认不作为正式印刷要求；关联[文印管理](features/02-文印管理.md)。
- **AC-06 计划不扣库存**：提交、退回、审批、预览和接单只记录计划，未领纸时不减少可用库存。
- **AC-07 实耗核对**：完整走通领纸、印制、损耗、余料退回与交付。使用以下示例核查：期初1000张，预计202张，实际领纸220张，可用库存变为780张；合格印品用纸200张、试印3张、错印5张，共耗208张，未用12张验收退回后库存为792张；完工核销不再次扣库。
- **AC-08 取消与重印**：未执行取消不影响库存；已耗用后取消不恢复已用纸；重印关联原任务并单独记录原因和实际耗材。
- **AC-09 交付确认**：印制完成进入待领取，指定领取人确认数量与质量后办结；有质量问题时保留原记录并继续处理。

### 2.3 物资领退

- **AC-10 部分发放与待补**：示例申请并批准10件，先发6件，库存只扣6件，领取人确认6件，仍有4件待补；后续补发或取消未发部分均可追溯；关联[物资领退](features/03-物资领退.md)。
- **AC-11 原单归还**：需归还物资关联原领用单，归还不能超过可归还数量；可再用物资验收回库，损坏物资不增加可用库存，损坏责任待核定时不自动免除归还责任。
- **AC-12 四类动作分开**：分别验证取消未发申请、纠正错误登记、实际归还和损坏处置，库存和记录按真实动作变化，不能互相替代。
- **AC-13 多本账一致**：同一发放或回收在领退、出入库、库存及报表中结果一致；重复确认不重复收发。

### 2.4 库存与盘点

- **AC-14 到货验收**：规格或数量不符时明确实收和差异，只有验收确认的数量进入可用库存；历史待核实数量不直接当作实收；关联[库存与盘点](features/04-库存与盘点.md)。
- **AC-15 缺货提醒**：实际库存不足时不按足量发放完成；低库存提醒关联真实物资，并有负责核查人员和处理结果。本期不要求完整采购流程。
- **AC-16 独立复核**：盘点差异有原因与依据，盘点人不能最终批准本人差异；驳回或退回后可复核，批准后形成可追溯调整。
- **AC-17 期间收发**：以明确盘点时点核对期间发生的正常入出库；盘点结果不覆盖遗漏这些收发，也不重复计入。

### 2.5 通知、台账与保留业务

- **AC-18 通知与任务分离**：重要通知按范围记录阅读确认，读通知不能自动办结关联任务；关联[通知与台账](features/05-通知与台账.md)。
- **AC-19 汇总与归档**：同一筛选条件下明细与汇总相符，费用估算与采购金额分开，办结资料可核查，导出范围与查看范围相同。
- **AC-20 既有业务保留**：预约确认、取消、核销及查询仍有真实结果，重复核销不重复计为到校；门户草稿、发布、更新和撤下不混淆内部材料；关联[招生接待与门户维护](features/06-招生接待与门户维护.md)。

### 2.6 四端一致性

- **AC-21 端职责覆盖**：管理后台、Web门户、小程序和App分别有用户、页面、导航、动作与边界说明，按[全端矩阵](ends/00-全端功能与协同矩阵.md)核查。已确认App功能仍为P1，规划覆盖不等于本期已交付。
- **AC-22 同事项跨端一致（P1）**：App接入时验证其与后台的原申请人、数量、状态、意见、交付和应还清单一致，跨端重复动作只产生一次有效业务；本期P0先验证后台内部闭环。
- **AC-23 外部预约一致**：Web和小程序对同一预约展示一致的确认、取消及到校状态，员工接待入口不向普通家长开放。
- **AC-24 终端不改变权限**：同一用户换端不扩大资料范围，不绕过审核、本人回避、独立盘点复核或领取确认。

### 2.7 正式学生与监护关系（P0，待开发验收）

- **AC-25 正式建档与历史**：新增含校区、全校唯一学号、姓名、班级、入学年度、在读／毕业／离校状态的正式学生，同名可区分，跨校区重复学号不能生效；转班保留历史，不改写原考试班级和通知快照。招生预约姓名和光荣榜不能作为正式学生档案；关联[学生与家长在校服务](features/07-学生与家长在校服务.md)。
- **AC-26 核实后激活**：班主任提交监护人姓名手机号关系，后台校方核实，再以真实本人手机号验证激活；手输手机号、微信昵称、知道学号或有招生预约均不能取得成绩权限。一个家长关联两孩、一孩有两家长分别可查；P0没有学生本人登录或查分入口。
- **AC-27 漏名邀请与异常**：未在名单的家长不能自助认领；校方核实补录后发定向、限时、一次有效邀请可激活，转发给他人、过期、重复使用或对象不符均不生效。号码异常、换号、换微信经校方核实处理并留痕，失效关系不可继续查看；微信身份、家长资格、员工权限互不自动授予。

### 2.8 成绩处理与发布（P0，待开发验收）

- **AC-28 Excel异常阻断**：按正式学生、考试和班级导入Excel，分别验证重复学生、未匹配、错误班级、越过科目满分、缺项等异常；未处理异常不能发布，不因已上传文件就向家长开放。
- **AC-29 分数与总分口径**：同一考试包含真实0分、缺考、免考、未录入样例，四者不同；显示各科满分与分数，缺考免考按已明确计分规则处理，未录入不默认为0，应计科目未齐不生成总分，齐全后总分与应计规则相符；无排名、等级、评语。
- **AC-30 发布、撤回和版本**：只发布某考试某班级，其他班级未发布记录不可见；当前有效家长可查关联孩子正式结果与历史。撤回后不可见，更正重新发布有新版本、原因和处理人，不覆盖原发布记录。
- **AC-31 私密资料范围**：普通访客、无关系家长、失效监护人、学生本人及无成绩授权员工，均无法通过列表、详情、历史、附件或导出取得该生成绩；毕业／离校停止家长资料访问且历史内部保留，Web不新增私密成绩入口，转班不丢失或重写内部历史。

### 2.9 家校通知（P0，待开发验收）

- **AC-32 学生范围快照与当前关系**：按班级发布后转班，原适用学生快照不改变；当前有效家长可见，失效家长不可继续访问，新核实的当前有效家长可查看其孩子适用通知；回执历史不被删除。
- **AC-33 逐家长回执与逐学生主统计**：一孩两家长分别打开、主动确认，已读与已确认分开；至少一位当前有效监护人主动确认后该学生计为已确认，另一家长保留真实状态。撤销已确认关系时旧回执留历史但不再满足当前主统计，新关联家长须自己确认；同一家长两孩分别记录，无有效家长学生仍为未确认并提示关系待核实，不能从学生快照静默剔除。

### 2.10 家校开放日送物（P0，待开发验收）

- **AC-34 独立配置与即约即成**：活动为单校区单日期，可含多个到校时段，跨校区或跨日另建活动；与招生游园独立配置报名起止、取消截止、人数限额、每单上限、适用学生和当面交接区域。满足资格与容量即成功，未开始、已截止、满额、已停办或不适用时不成功；关联[家校开放日送物预约](features/08-家校开放日送物预约.md)。
- **AC-35 合单与按人占位**：同家长同活动看两个孩子合一单且共用同一时段，2位实名到访人员只占2人，孩子数不另占位；原单保留原时段和完全相同实名人员名单可追加适用有效关联孩子，不增加占位，改变时段或人员不能作为追加。另一日期或校区活动可另约；同单重复人员不重复计数，超每单上限失败，竞争最后名额不超总限额。
- **AC-36 同孩唯一与隐私**：一孩两家长同时提交，仅一有效单；同孩子同活动跨场次也不能再建有效单。另一监护人仅见本人孩子已约，不见订单其他孩子、访客姓名和联系方式；同行到访不取得正式学生资料或成绩权。
- **AC-37 取消、释放与重约风险**：订单无人入校且截止前可取消并释放原占位，重复取消不重复释放，原凭证失效；截止后或已有任一人员入校不得按未入校规则取消。P0改期明确为取消后重约，操作前提示原名额不保留、目标可能满额，无候补和正式改期承诺。
- **AC-38 分批入校与重复处理**：3人订单分批1人、2人登记，实际入校依次为1、3，重复扫码仍为3，未到同行不自动入校；记录实际人员、时间和办理人，无效、已取消、停办凭证不能作为有效入校安排。
- **AC-39 离校来源与统计边界**：分别验证工作人员登记、家长自报、核实补录，来源可区分且不强制；无记录不显示“仍在校”，活动结束不自动改“已离校”。指标固定为“已入校未登记离校人数”，不得称实时在校人数；人员离校不释放本场预约总接待容量。
- **AC-40 停办与历史保留**：停办通知受影响家长并失效凭证，通知未送达不冒充已送达；原订单、已发生入校和离校历史保留，停办不删除事实、不继续接受有效预约。
- **AC-41 当面送物范围**：学校指引明确入校当面交接区域，页面不产生物品代收、保管或物流签收流程，不承诺硬件门禁、人脸识别或强制出校。活动出入记录不替代学生考勤。

## 3. 统一通过条件

- 本期范围内的正常流程与关键异常场景均有实际操作记录和责任岗位确认。
- 每个未结事项有当前环节、责任人和下一步；没有无人认领却被标为完成的事项。
- 实际收发、消耗、退回、更正与各类台账、库存和报表保持一致；不重复扣账、不凭作废虚增库存。
- 必要的资料访问、独立复核和领取确认规则得到验证，敏感资料查看问题不能以页面已存在为由关闭。
- 正式学生、监护资格、成绩发布与撤回、家校通知学生口径及开放日防重容量和隐私均有实际验证；不得用招生姓名、光荣榜、内部公告或演示页面替代新能力。
- 历史记录、未结事项和新口径之间有对账依据。无法还原的差异单独列出，核定处置，不编造明细。
- 未通过项有影响、责任人和处置安排；影响授权、实际收发、交付确认或账实一致的问题未关闭时，不宣称本期整体验收通过。

## 4. 试运行指标

| 指标 | 统计口径 | 用途 |
| --- | --- | --- |
| 线上办理占比 | 试运行范围内有完整线上记录的事项数／应纳入线上办理事项数 | 判断线下流程迁移程度 |
| 平均处理时长 | 提交至办结的实际时长，另列等待申请人补充和缺货等时间 | 判断流程停滞与岗位负担 |
| 超期率 | 已超过约定期限的事项数／同范围应按期处理事项数 | 发现延误及常见原因 |
| 交付确认率 | 已有有效领取确认的应确认事项数／已交付且应确认事项数 | 检查经办完成与实际交付是否贯通 |
| 重复登记率 | 经核实的重复事项数／同范围正式登记事项数 | 检查重复录入与重印、补发区分 |
| 库存差异率 | 同一盘点范围内存在差异的物资种类数／已盘物资种类数，另列差异数量与原因 | 检查库存基础与收发口径 |
| 家校通知学生确认率 | 至少一位当前有效监护人主动确认的学生数／该通知应确认学生快照数，逐家长明细另列 | 发现尚无家长确认的家庭，不混作家长人数比例 |
| 开放日实际入校人数 | 授权活动／校区／场次中已登记入校的去重实名人员数 | 与预约人数分别核查，分批和重复登记不重复计人 |
| 已入校未登记离校人数 | 同范围已入校且无离校登记的去重人员数，来源可查 | 提示记录待核查，不能解释为实时在校人数 |

先确定试运行范围和基线，再由学校设置改善目标。不同期间使用一致口径；不存在当前项目已经达到的预设比例或效能评分。

## 5. 验收记录要求

每个场景记录验收日期、责任岗位、样例或事项编号、预期结果、实际结果、通过／未通过、问题及复核结论。历史模拟验证或构建检查不能直接代替真实岗位业务验收。P1／P2功能分别列为后续需求，不计作本期已通过能力。
