# 校园行政办公产品规划

更新日期：2026-11-05。本文为产品规划基线，现有能力依据项目静态梳理；本次已确认将学生与家长在校服务、家校开放日送物预约纳入P0首批开发，均为待开发目标；App仍按P1迭代。本期目标不代表已经实现或通过业务验收。

## 1. 产品定位与核心价值

### 1.1 现有项目梳理

现有项目已具备以下业务基础：

- **行政基础资料**：教职工、部门、岗位、班级、角色与权限管理。
- **文印管理**：文印登记、聊天信息辅助录入、附件与印刷要求核对、完成与作废、耗材统计。
- **物资管理**：物品与供应商档案、套装配置、领用与回收、出入库、库存预警、盘点及报表。
- **招生接待**：访校预约、接待安排、到校核销、取消及沟通备注。
- **信息发布**：内部通知公告、官网资讯及学校展示内容维护。

目前主要以**经办登记和台账统计**为中心，申请、审批、任务交接、领取确认、异常处理等环节尚未完整贯通。现有文印登记不能等同于完整文印审批流程，官网内容发布也不能等同于内部公文流转。

### 1.2 产品定位

**面向学校行政人员的校园事务协同办理平台。**

以文印、物资领退、库存管理等已有高频业务为切入点，把分散在纸质单据、聊天消息和口头交接中的事项，转变为有明确责任人、处理进度、交付结果和可查记录的线上流程。

行政人员是核心用户，教职工是申请与确认的协作用户，部门负责人承担审核与督办职责。在此主线上，小程序补齐入学前预约游园与入学后在校服务：学校核实监护关系后，家长查看本人有效关联孩子的已发布分数和历史，接收家校通知，并预约学校开放日到校当面送物。文中在校服务“本人”指登录家长及其有效关联孩子，P0不提供学生本人登录访问。

### 1.3 核心价值

- **减少重复登记**：同一事项一次提交，后续办理沿用原有资料。
- **减少沟通追问**：申请人能查进度，经办人能看清要求和下一步。
- **明确岗位责任**：每个事项都有当前处理人、办理期限和完成标准。
- **保证账实一致**：申请数量、实际发放、退回、损耗分别记录，单据与库存相互对应。
- **方便核查交接**：审批意见、附件、交付凭证和更正原因随事项保留。
- **减少家校信息差**：以正式学生档案、核实后的监护关系和学校正式发布为依据，向当前有效监护人提供关联孩子的必要信息，减少成绩转发、通知漏收和开放日到访冲突。

成效以线上办理占比、平均处理时长、超期率、重复登记率、交付确认率和库存差异率衡量，试运行后建立基线并确定改善目标。

### 1.4 全端产品形态

- **管理后台**：行政、教务、总务等岗位集中受理、分派、复杂办理、盘点复核和对账；新增最小正式学生档案、监护关系核实、Excel成绩处理与发布、家校通知、开放日配置和现场台账。
- **Web门户**：家长、学生及访客浏览学校公开信息，发起和查询入学前招生游园预约；不承载私密成绩和在校家长服务。
- **微信小程序**：入学前预约游园与查凭证；入学后家长按当前有效关系查看孩子分数历史、家校通知、开放日送物预约；已核实并获授权的工作人员使用对应接待与现场登记入口。
- **App**：教职工、班主任、行政人员和负责人移动申请、补充、查询、审核、接单、领取与归还确认。

四端功能分工、页面和跨端主流程见[全端功能与协同矩阵](ends/00-全端功能与协同矩阵.md)。P0内部行政流程通过管理后台按岗位授权的办事入口完成申请、审批、办理和确认；2026-11-05确认的家长学生服务由小程序与后台共同承载，App核心移动闭环仍按P1迭代。

## 2. 用户角色与核心使用场景

以下按业务职责划分，同一人可以兼任多个角色。

### 2.1 行政／教务经办人员

- 受理教职工申请，检查材料并安排办理。
- 按教师、班级或部门组织教材、办公用品发放与回收。
- 查询未办事项、处理异常并汇总日常台账。

### 2.2 文印工作人员

- 核对原稿、份数、纸型、单双面及交付时间。
- 接单排期，记录领纸、印制、损耗和余料退回。
- 完成交付，处理补印、重印及领取异常。

### 2.3 总务／仓库管理人员

- 核验到货物资，办理入库并维护库存资料。
- 按领用事项备货、发放、接收退还。
- 处理低库存提醒，开展盘点和差异核查。

### 2.4 部门负责人／校级管理人员

- 审批超量领用、特殊文印及库存差异调整。
- 查看超期事项，协调跨岗位办理与人员交接。
- 核查部门用量、异常损耗和月度汇总。

### 2.5 招生行政／接待人员

- 确认访校预约，安排接待人员与时间。
- 登记到校、核销凭证并处理取消或异常预约。
- 记录接待沟通情况，汇总预约与到访情况。

### 2.6 宣传／信息发布人员

- 编辑和发布校园资讯、通知及招生信息。
- 维护学校介绍、教师展示、校园设施和常见问答。
- 检查对外内容，更新或撤下失效信息。

### 2.7 平台业务管理员

- 维护部门、人员、班级及岗位职责。
- 分配业务权限，处理换岗、离职和待办交接。
- 维护物资分类、常用套装及学校办事规则。

### 2.8 教职工／班主任（协作角色）

- 提交文印或物资申请，补充必要材料。
- 查询办理进度，回应退回补充要求；班主任收集并核实负责班级的监护人姓名、手机号及关系，向校方提交关联资料。
- 确认印品、物资领取，办理归还或差异反馈。

### 2.9 在校家长／监护人

- 经校方核实监护关系并完成真实手机号验证后激活，切换查看本人关联的一个或多个孩子及其已发布分数历史。
- 查看孩子适用的家校通知，分别记录阅读与确认，了解仍需确认的安排。
- 为适用孩子预约开放日送物，填写实名到访人员，查询凭证，按规则取消并到校当面交接物品。

### 2.10 在校服务教务／家校工作人员

- 维护正式学生档案，核实班主任提交的监护资料，处理补录、关系失效和异常绑定。
- 从Excel导入考试分数，处理匹配或分数异常，按考试与班级发布、撤回或更正，并核查通知回执。
- 配置家校开放日及人数容量，现场按实际人员登记入校，按来源登记离校并核查异常。

## 3. 功能清单

优先级针对本轮新增和完善工作。已有能力继续沿用；完整审批、领取确认、真实任务提醒和本次确认的在校家长学生服务均属于待开发或待完善环节。

### 3.1 P0 核心必做

- **组织、人员与业务权限管理（已有能力完善）**  
  **适用角色：**平台业务管理员、行政经办人员、部门负责人。  
  **操作流程简述：**维护组织与人员资料 → 分配岗位和业务范围 → 明确审核人与经办人 → 岗位变动时交接未办事项。  
  **业务价值：**保证事项流向正确，限制试卷、人员联系方式等资料的查看范围。

- **行政工作台与真实待办（重点完善）**  
  **适用角色：**全部内部用户。  
  **操作流程简述：**进入工作台 → 查看“我的申请、待我处理、我经办、已办事项” → 打开具体事项 → 完成对应动作。  
  **业务价值：**集中安排当天工作；待办和统计均对应实际业务，无记录时明确显示为空。

- **文印需求统一受理（已有能力完善）**  
  **适用角色：**教职工、行政／教务经办人员、文印工作人员。  
  **操作流程简述：**本人提交或行政代录 → 提供原稿与要求 → 核对教师、班级、份数、纸型、单双面及期限 → 确认受理。聊天导入内容逐条人工核实。  
  **业务价值：**减少口头遗漏、重复录入和印刷要求不清造成的返工。

- **固定审批与任务交接（本期新增）**  
  **适用角色：**申请人、部门负责人、行政经办人员。  
  **操作流程简述：**按文印、领用等固定规则判断是否需审批 → 审核通过、拒绝或退回补充 → 指定经办人 → 经办人接单。  
  **业务价值：**明确授权和责任；日常低值、高频事项可按规定直接办理，超量或特殊事项再审批。

- **文印执行、耗材核算与领取确认（已有能力完善）**  
  **适用角色：**文印工作人员、仓库管理人员、申请人。  
  **操作流程简述：**接单排期 → 领纸出库 → 印制并记录损耗 → 核对余料退回 → 通知领取 → 领取人确认数量与质量 → 办结。  
  **业务价值：**贯通需求、实际耗用和交付结果，避免“标记完成但尚未交付”。

- **物资申请、发放与归还（已有能力完善）**  
  **适用角色：**教职工、班主任、行政经办人员、仓库管理人员。  
  **操作流程简述：**选择单品或套装申请 → 按规则审核 → 备货与发放 → 领取确认 → 需归还物资关联原单办理退还。支持部分发放和缺货待补。  
  **业务价值：**查清谁领了什么、实际发了多少、还欠多少、应归还多少。

- **库存收发、到货验收与缺货提醒（已有能力完善）**  
  **适用角色：**仓库管理人员、行政经办人员。  
  **操作流程简述：**核对到货数量、规格与凭证 → 确认验收入库；实际发放时出库 → 检查库存余量 → 低库存形成待处理提醒。  
  **业务价值：**保持库存可用量清晰，减少漏记、重复出库和临时缺货。

- **盘点复核与业务纠错（已有能力完善）**  
  **适用角色：**仓库管理人员、行政经办人员、部门负责人。  
  **操作流程简述：**发起盘点 → 登记实盘与差异原因 → 必要时复盘 → 独立负责人审核 → 调整库存并留档；错误单据通过有原因的更正处理。  
  **业务价值：**让账实差异有依据、调整有责任，避免直接改数后无法追溯。

- **内部通知与办理提醒（已有能力完善）**  
  **适用角色：**行政经办人员、部门负责人、相关教职工。  
  **操作流程简述：**选择接收范围发布通知 → 接收人查看；事项提交、退回、待领取、超期时提醒对应人员 → 处理后更新状态。  
  **业务价值：**减少群消息遗漏；重要通知增加阅读确认，办理完成以实际回执为准。

- **统一台账、办结归档与基础报表（已有能力完善）**  
  **适用角色：**行政经办人员、仓库管理人员、部门负责人。  
  **操作流程简述：**按人员、班级、部门、物品及时间查询 → 查看来源单据和处理记录 → 汇总用量、损耗与办理情况 → 导出归档。  
  **业务价值：**减少月底重新汇总，保证库存、领退、文印和报表口径一致；估算费用与实际采购金额分开呈现。

- **正式学生档案与监护关系激活（P0，已确认待开发）**  
  **适用角色：**教务、班主任、校方核实人员、家长。  
  **操作流程简述：**建立含校区、全校唯一学号、姓名、班级、入学年度、在读／毕业／离校状态及转班历史的正式档案 → 班主任收集监护人姓名、手机号、关系 → 后台核实关联 → 家长验证真实本人手机号后激活。名单遗漏由校方补录后发送定向、限时、一次有效邀请。  
  **业务价值：**为一人多孩、一孩多监护人提供可信基础，避免凭预约姓名、光荣榜、手输手机号或微信昵称取得成绩；异常手机号和换微信由校方核实处理，毕业／离校停止家长资料访问并内部保留历史。

- **家长关联孩子分数与历史查询（P0，已确认待开发）**  
  **适用角色：**教务、授权发布人员、有效监护人。  
  **操作流程简述：**后台Excel导入 → 核对考试、班级、正式学生及科目满分 → 处理异常 → 按考试＋班级正式发布 → 小程序家长按当前有效监护关系查孩子分数与历史；必要时撤回并以新版本更正。  
  **业务价值：**提供学校正式分数，区分零分、缺考、免考、未录入；仅应计科目齐全时显示总分，不提供排名、等级或评语。

- **学生维度家校通知与确认（P0，已确认待开发）**  
  **适用角色：**班主任、家校发布人员、有效监护人。  
  **操作流程简述：**选择适用学生形成发布时接收范围快照 → 发布 → 当前有效家长查看 → 分别记录每位家长的阅读与主动确认 → 按学生核查是否至少一位当前有效监护人已确认。  
  **业务价值：**覆盖一孩多监护人，明确“已读”和“已确认”的区别；主统计按学生计算，不因多个家长重复扩大应确认数。

- **家校开放日配置与送物预约（P0，已确认待开发）**  
  **适用角色：**学校活动管理人员、有效监护人、现场工作人员。  
  **操作流程简述：**学校设置校区、日期时段、报名起止、取消截止、人数限额、每单人数上限、适用学生及交接区域 → 家长选择适用孩子及实名到访人员 → 有名额即成功 → 出示凭证到校当面送物。  
  **业务价值：**独立于入学前招生游园，按实名到访人员人数控制接待容量；同家长同场同校区多孩合并一单，每孩子同活动最多一有效单，两位家长同时预约仅一方成功。

- **开放日取消、停办与人员出入记录（P0，已确认待开发）**  
  **适用角色：**预约家长、现场工作人员、活动管理人员。  
  **操作流程简述：**未入校且取消截止前取消释放名额 → 活动停办时通知、失效凭证并保留已发生历史 → 按实际实名人员分批登记入校 → 可由工作人员、家长自报或核实补录离校并注明来源 → 核查台账。  
  **业务价值：**重复入校不重复计人，离校不释放本场总接待容量；未登记离校不等于仍在校，活动结束不自动记为已离校，统计使用“已入校未登记离校人数”。

### 3.2 P1 重要迭代

- **采购申请与补货协同**  
  **适用角色：**行政经办人员、仓库管理人员、采购经办人员、部门负责人。  
  **操作流程简述：**缺货或部门需求发起 → 汇总并审批 → 采购办理 → 到货验收 → 入库 → 关闭需求。  
  **业务价值：**把库存预警落实为补货事项，减少重复采购与需求遗漏。

- **校园报修管理**  
  **适用角色：**教职工、总务人员、维修人员。  
  **操作流程简述：**提交位置、问题和照片 → 总务受理派工 → 维修反馈 → 申请人验收 → 办结或返修。  
  **业务价值：**让维修进度可查，明确受理、维修和验收责任。

- **会议室与公共资源预约**  
  **适用角色：**行政人员、教职工、资源管理人员。  
  **操作流程简述：**查看可用时段 → 提交用途与需求 → 确认或审批 → 使用 → 取消、变更或完成登记。  
  **业务价值：**减少场地冲突和重复安排。

- **招生接待跟进完善**  
  **适用角色：**招生行政人员、接待人员、招生负责人。  
  **操作流程简述：**沿用预约与核销业务 → 统一确认规则 → 安排接待任务 → 处理改期、未到访 → 记录回访与下一步。  
  **业务价值：**减少漏接待和漏回访，明确预约归属与接待责任。

- **门户内容审核与发布管理**  
  **适用角色：**宣传人员、内容审核负责人。  
  **操作流程简述：**编辑草稿 → 提交审核 → 退回修改或批准发布 → 更新、撤回并保留记录。  
  **业务价值：**在现有内容维护基础上统一对外口径，降低误发布风险。

- **移动待办与现场办理**  
  **适用角色：**部门负责人、行政经办人员、文印及仓库工作人员。  
  **操作流程简述：**查看本人待办 → 审批或接单 → 现场拍照、交付确认或到校核销 → 查看真实办理结果。  
  **业务价值：**支持离开办公桌后的高频动作，减少事后补录。

- **开放日候补与正式改期**  
  **适用角色：**家长、活动管理人员。  
  **操作流程简述：**满额登记候补 → 按后续确认规则补位；有目标场次名额时办理正式改期并同步凭证。  
  **业务价值：**减少人工协调；P0仅支持符合取消条件时取消后重约，并告知目标场次可能已满、原名额不保留。

- **成绩疑问与同口径趋势（P1）**  
  **适用角色：**有效监护人、教务。  
  **操作流程简述：**对已发布记录提出疑问 → 教务核查回复或更正 → 仅在考试科目、满分及计分范围可比时展示趋势。  
  **业务价值：**保留疑问处理依据，避免把不同满分或科目范围的分数直接比较；不扩展为排名或智能评价。

### 3.3 P2 远期规划

- **固定资产全生命周期管理**  
  **适用角色：**资产管理人员、部门负责人、资产使用人。  
  **操作流程简述：**验收建档 → 领用保管 → 调拨、借还与维修 → 盘点 → 报废审批。  
  **业务价值：**从消耗性物资管理延伸到设备与耐用品责任管理。

- **教职工入职、转岗与离职交接**  
  **适用角色：**人事行政人员、部门负责人、教职工。  
  **操作流程简述：**发起人员变动事项 → 分派资料、物资和权限交接任务 → 各岗位确认 → 汇总办结。  
  **业务价值：**减少手续遗漏及未归还物资、未交接事项。

- **内部公文与用印流转**  
  **适用角色：**办公室人员、部门负责人、印章保管人员。  
  **操作流程简述：**拟稿或提交用印申请 → 审核会签 → 签发或批准 → 分发、用印登记 → 归档。  
  **业务价值：**规范正式文件和印章使用，建立完整责任记录。

- **多校区协同与管理分析**  
  **适用角色：**校级管理人员、校区负责人、行政主管。  
  **操作流程简述：**按校区汇总业务 → 协调物资调拨与跨校区事项 → 比较办理效率、消耗和异常 → 跟踪改善。  
  **业务价值：**在单校区流程稳定后支持统一管理与资源调配。

- **学生请假、考勤与作业服务**  
  **适用角色：**学生、有效监护人、班主任、教务。  
  **操作流程简述：**在后续版本分别明确请假申请与审批、考勤记录与异常核实、作业布置与反馈规则后，再接入在校服务入口。  
  **业务价值：**在身份和正式档案稳定后延伸日常家校服务；本期不交付这些流程。

- **学生本人直接访问在校服务（P2）**  
  **适用角色：**学生、教务。  
  **操作流程简述：**后续独立确定学生本人身份核实、登录、资料访问及未成年人使用规则 → 再规划本人查询入口。  
  **业务价值：**为学生直接使用建立独立资格；P0只提供家长对有效关联孩子的访问，不复用监护关系授予学生身份。

## 4. 核心业务主流程

### 4.1 文印办理主流程

1. 用户进入工作台，发起文印需求；行政代录时注明原申请人。
2. 提交原稿、印刷要求、用途、领取人和期望完成时间。
3. 受理人员核对内容，缺少原稿或要求不明确时退回补充。
4. 按学校规则决定直接受理或提交负责人审批；通过后进入待接单。
5. 文印人员接单、确认排期，核查耗材；缺货或无法按期完成时反馈处理方案。
6. 实际领纸时办理出库，完成印制后记录合格印品、试印损耗和未用余料退回。
7. 通知领取，领取人核对数量与质量；存在问题时进入补印或重新处理。
8. 交付确认与耗材去向核对均完成后办结，保存原稿、审批意见、耗材明细和交付记录；余料或数量差异未核清时继续保留核销待办。

**异常规则：**未执行需求可以撤回或取消；已经耗用的纸张保留实际消耗，不能因作废而直接恢复为可用库存。重印须明确原因并关联原事项。

### 4.2 物资领用与归还主流程

1. 用户进入工作台，选择物品或常用套装，填写用途、数量和领取对象。
2. 按规则直接受理或提交审批，明确批准数量。
3. 仓库核对库存并备货；不足时选择部分发放、等待补货或取消未发部分。
4. 经办人按实际数量发放并记录出库。
5. 领取人确认品类与数量，未发部分继续保留待办。
6. 对需归还物资记录应还数量；归还时关联原领用记录并检查状态。
7. 可再次使用的物资验收回库，损坏物资记录处置结果，更新未还数量。
8. 全部获准物资已交付或未发部分明确取消后，领用申请办结；需归还物资继续保留应还清单，实物归还与损坏、遗失等责任处理均明确后再结清归还事项。领用、退回、库存和统计记录保持一致。

**异常规则：**取消申请、纠正错误登记、实际归还和损坏报废分别处理，并保留原因、数量及责任人。

### 4.3 库存盘点与差异处理主流程

1. 仓库人员进入工作台，选择盘点范围和盘点时点。
2. 核对实物数量，登记实盘数、差异原因及凭证。
3. 对差异较大的物品安排复盘，核查漏记收发、损坏或单位换算问题。
4. 提交行政负责人审核，盘点经办与最终批准分开承担。
5. 审核通过后调整库存，留存调整依据；审核未通过则退回核查。
6. 归档盘点结果，形成待处理问题并跟踪关闭。

**异常规则：**盘点期间发生的正常收发单独核对归属，避免遗漏或重复计入。

### 4.4 学生档案、监护关系与分数查询主流程

1. 教务建立或导入正式学生档案，校验全校唯一学号及校区、姓名、班级、入学年度和在读状态；转班保留历史。
2. 班主任收集监护人姓名、手机号、与学生关系，校方在后台核实后关联；一位监护人可关联多个孩子，一名学生可关联多个有效监护人。
3. 家长登录小程序并验证真实本人手机号，匹配校方核实关系后激活；手输手机号、微信昵称和招生预约资料均不能取得成绩权限。遗漏名单由校方补录后发定向、限时、一次有效邀请，异常号码、换号和换微信经校方核实处理。
4. 教务从Excel导入考试与分数，核对正式学号、考试班级、科目满分、分数及应计范围，处理重复、未匹配、越界和未录入等异常；零分、缺考、免考与未录入分别记录。
5. 无未处理异常后，授权人员按考试＋班级正式发布；只有应计科目齐全才显示总分，缺考／免考按该考试明确规则处理，不能擅自当零分。
6. 家长按当前有效监护关系，在小程序查看关联孩子已发布分数和历史；转班不改写考试发生时班级，关系失效或学生毕业／离校后停止家长资料访问，历史内部保留。
7. 发布内容有误时撤回，撤回后小程序不可见；教务修正后以新版本发布，保留原因、版本、发布人与时间。

### 4.5 家校通知主流程

1. 发布人选择学生或班级，将当时适用学生固化为接收范围快照，并设定是否需要主动确认。
2. 发布后，当前有效监护人可查看关联孩子适用通知；家长关系变化不改写原适用学生快照，无有效关系者不能继续查看。
3. 每位家长的打开阅读和主动确认分别留痕；同一人多孩按学生分别记录。
4. 发布人按学生核查应确认、至少一位当前有效监护人主动确认、尚无当前有效监护人主动确认，必要时再查逐家长明细；失效关系旧回执内部保留，不代替现关联家长确认，一名家长确认不冒充其他家长已读或已确认。

### 4.6 家校开放日送物主流程

1. 学校独立配置活动：一场活动对应单校区、单日期的一次开放安排，可含多个到校时段；跨校区或跨日分别建活动。明确报名起止、取消截止、人数容量、每单人数上限、适用学生、实名到访要求和当面交接区域。
2. 有效监护人进入小程序，选择适用孩子；同家长同活动仅一有效单，多孩共用同一时段与实名到访人员，以人数占位而非孩子数。允许在原有效订单追加适用且有效关联孩子，沿用原时段和原实名人员名单，不增加占位；参加另一日期或校区的活动可另约。
3. 提交时同时检查资格、容量与孩子重复预约；有名额即成功。同一孩子同活动仅一有效订单，两位家长同时提交只允许一方成功；其他监护人只看到本人孩子已约，不获得该单其他孩子或访客资料。
4. 家长查询有效凭证和当面交接指引。未入校且截止前可取消并释放名额；P0改期为取消后重约，提前告知原名额不保留和目标场次满额风险。
5. 工作人员核对当前有效订单与实际实名到访人员，可分批登记入校；重复操作不重复计人，同行人员不因到访取得学生或成绩权限。
6. 家长入校当面送物；离校可由工作人员登记、家长自报或经核实补录，分别记录来源。离校登记非强制，无记录不推断仍在校，结束不自动补“已离校”，离校也不释放该场总接待容量。
7. 学校停办时通知受影响家长并使凭证失效，保留原预约、已发生入校与离校历史；台账展示预约人数、实际入校人数及“已入校未登记离校人数”，不称为实时在校人数。

## 5. 本期项目的边界与不包含的功能

### 5.1 本期交付边界

- **围绕现有学校业务开展**：保留文印、物资领退、库存三条行政主线，同时交付已确认的最小学生档案、监护关系、分数历史、家校通知及家校开放日送物P0首批。
- **采用明确的固定流程**：确定申请人、审核人、经办人和确认人，覆盖退回、取消、部分交付、缺货、损耗及更正。
- **保留必要代办**：允许行政人员代录纸质或聊天需求，同时保留原申请人和来源。
- **统一业务记录**：申请记录预计需求，实际领料、发放、退回和损耗形成实际账目。
- **保留已有关联业务**：访校预约、到校核销、门户内容和喜报维护继续使用；本期只处理必要的职责、状态和信息口径衔接。
- **以真实办结为验收标准**：事项能够找到当前责任人、查询进度、确认交付、追溯异常，并与库存及报表核对。
- **身份与资格分别管理**：微信身份、家长资格、员工权限独立核实与授权；兼具身份不互相授予权限。新在校服务详见[学生与家长在校服务](features/07-学生与家长在校服务.md)与[家校开放日送物预约](features/08-家校开放日送物预约.md)。

### 5.2 本期不包含的功能

- 完整教务教学和学籍管理，包括排课调课、招生录取转学手续、考试组织、排名、等级、评语和学习平台；本期仅提供正式学生最小档案、Excel分数处理发布和家长有效关联孩子已发布分数历史。学生本人直接登录与访问留P2。
- 完整招生管理，包括渠道营销、佣金结算、录取、报名收费和退款。
- 财务核算、预算、报销、付款、工资及税务管理。
- 完整人事考勤、请假出差、合同、公文和用印体系。
- 全校固定资产生命周期管理和跨校区统一调度。
- 官网整体重建；超出本期已确认范围的家长学生综合服务，包括P2学生请假、考勤和作业。
- 家校开放日物品代收、保管、物流配送或物流签收；硬件门禁、人脸识别、强制出校登记及实时在校人数承诺。
- 任意自定义的复杂审批流程、跨部门多级会签及流程设计工具。
- 扫描设备直传、打印设备自动执行等设备联动。
- 未经人工确认就提交申请、批准事项或变更库存的自动办理。
- 在业务数据尚未完善前推出综合效能评分、预测或智能决策功能。
