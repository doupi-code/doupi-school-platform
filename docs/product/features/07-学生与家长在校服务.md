# 学生与家长在校服务

更新日期：2026-11-05。状态：已确认纳入P0首批开发，当前待开发、待实际业务验收。本文件不表示现有后台已经具备正式学生、监护关系或成绩服务。

## 1. 产品定位与核心价值

在保留校园行政办公主线与入学前招生游园的基础上，面向在校家长提供最小可信的孩子在校服务：校方维护正式学生档案、核实监护关系，教务从Excel处理并发布分数，小程序家长按当前有效监护关系查询孩子已发布分数与历史、接收家校通知。在校服务中的“本人”指登录家长及其有效关联孩子，P0不提供学生本人登录访问。

目前后台有教师与班级资料，尚无正式学生档案。招生预约中的学生姓名、公开光荣榜和教师班级资料均不能替代正式学生身份。本期必须先建立最小正式学生档案，才能承载成绩、通知和[家校开放日送物预约](08-家校开放日送物预约.md)。

核心价值是减少分数私下转发和家长身份误认，提供可撤回、可更正的正式结果，并使重要安排能按学生核查确认情况。微信身份、家长资格与学校员工权限分别核实，登录成功不等于取得任何学生资料权限。

## 2. 用户角色与核心使用场景

### 2.1 教务／正式学生档案管理人员

- 建立校区、全校唯一学号、姓名、班级、入学年度及在读／毕业／离校状态，核实并记录转班历史。
- 从Excel导入考试分数，处理学生匹配、重复、满分越界和缺项等异常后，按考试＋班级发布。
- 撤回错误发布、保留原因，以新版本更正；处理校方核实后的身份与关系异常。

### 2.2 班主任／家校发布人员

- 收集负责班级监护人的姓名、手机号与关系，提交后台核实关联，不自行凭聊天昵称或预约姓名授予成绩权限。
- 对负责范围内学生发布通知，核对学生接收范围快照和逐学生确认情况。
- 对未确认家庭跟进，名单遗漏时由校方核实补录，再发定向、限时、一次有效邀请。

### 2.3 家长／有效监护人

- 验证真实本人手机号并激活已核实关系，切换本人关联的多个孩子；一个孩子可有多个有效监护人。
- 查询孩子正式发布的各科满分、分数、符合条件的总分及历史，理解零分、缺考、免考和未录入的区别。
- 查看适用通知并主动确认；监护关系或手机号异常、换微信时联系校方核实处理。

## 3. 功能清单

### 3.1 P0 核心必做

- **STU-01 最小正式学生档案（已确认待开发）**  
  **适用角色：**教务、授权档案管理人员、班主任。  
  **操作流程：**新建或批量导入 → 校验全校唯一学号 → 核对校区、姓名、班级、入学年度、状态 → 生效 → 记录转班起止与变更原因。  
  **业务价值：**为监护关系、考试与活动建立稳定对象。姓名可重复，学号不能跨校区重复；转班不改写历史考试班级和已发布通知快照。毕业或离校后停止家长资料访问、不可再预约在读活动，历史由校方内部保留。

- **GUA-01 监护关系核实与激活（已确认待开发）**  
  **适用角色：**班主任、校方核实人员、家长。  
  **操作流程：**班主任收集监护人姓名、手机号、关系和对应学生 → 后台核实关联 → 家长登录并完成真实本人手机号验证 → 匹配后激活 → 关系失效时停止相关访问。  
  **业务价值：**支持一人多孩子、一孩多监护人；系统不能因手输某个手机号、微信昵称、知道学生姓名或拥有招生预约而开放成绩。本人手机号核验只证明号码持有，不替代校方监护资格核实。

- **GUA-02 漏名补录、邀请与异常处理（已确认待开发）**  
  **适用角色：**家长、班主任、校方核实人员。  
  **操作流程：**发现未匹配 → 向校方提供必要核实信息 → 校方补录或更正正式关系 → 发送定向、限时、一次有效邀请 → 核验本人手机号后完成激活；换号、号码冲突或换微信由校方核实后调整。  
  **业务价值：**为漏名单家庭提供实际入口，防止公开自助认领、可转发通用邀请或手机号输入成为权限旁路。过期、已使用、不匹配邀请不得激活；更换微信不复制出两套无约束资格。

- **GRD-01 Excel导入与异常处理（已确认待开发）**  
  **适用角色：**教务、授权成绩处理人员。  
  **操作流程：**确定考试、学期、班级、科目满分及应计规则 → 上传Excel → 按正式学生匹配 → 预览检查 → 处理重复、未匹配、错误班级、分数越界及未录入等异常 → 确认待发布批次。  
  **业务价值：**将分数处理集中在后台；未处理异常不能发布。零分为真实数值，缺考、免考、未录入为不同状态，不能用空值或统一的0混写。明确应计科目与缺考／免考处理规则，只有应计科目齐全且计分规则完整时生成总分，否则明确未生成及原因。

- **GRD-02 按考试＋班级发布、撤回与更正（已确认待开发）**  
  **适用角色：**教务、授权发布人员。  
  **操作流程：**检查无未处理异常 → 选择考试和班级 → 确认正式发布 → 有误时撤回并说明原因 → 修正后发布新版本。  
  **业务价值：**分批发布不泄露其他班级未发布分数；未发布和已撤回记录在学生家长端不可见。保留处理人、发布时间、撤回原因、版本及更正差异，不覆盖历史发布责任。

- **GRD-03 家长关联孩子已发布分数与历史（已确认待开发）**  
  **适用角色：**当前有效监护人。  
  **操作流程：**选择家长有效关联孩子 → 按考试、学期查询 → 查看各科满分、分数／特殊状态、符合条件的总分和版本 → 查看历史。  
  **业务价值：**提供正式记录，禁止查看其他学生分数，不显示排名、等级、评语。转班不改写考试时班级；关系失效或学生毕业／离校停止家长访问，历史内部保留。

- **FAM-01 学生维度家校通知与回执（已确认待开发）**  
  **适用角色：**班主任、授权发布人员、当前有效监护人。  
  **操作流程：**选定学生／班级 → 固化发布时适用学生快照 → 发布并明确是否要求家长确认 → 每位家长分别阅读和主动确认 → 按学生核查至少一位当前有效监护人确认情况。  
  **业务价值：**学生接收范围不因后续转班重算；查看权限仍按当前有效监护关系判断。逐家长保留未读／已读、未确认／已确认及时间；主统计为应确认学生数、已有至少一位当前有效监护人主动确认的学生数、尚无当前有效监护人主动确认的学生数，另提供逐家长明细。失效关系旧回执保留历史，但不替代现关联家长确认；新关联家长须自己确认。同一家长多孩按学生分别确认，一个家长确认不等于其他家长已读或已确认，打开通知也不等于主动确认。

### 3.2 P1 重要迭代

- **成绩疑问与同口径趋势**  
  **适用角色：**有效监护人、教务。  
  **操作流程：**对正式记录提出疑问 → 教务核查回复或关联更正 → 在科目、满分及计分范围可比时查看趋势。  
  **业务价值：**形成疑问处理闭环，避免直接比较不同考试口径；不引入排名、等级或评语。

### 3.3 P2 远期规划

- **学生本人直接访问在校服务**  
  **适用角色：**学生、教务。  
  **操作流程：**后续独立确定学生身份核实、登录、资料访问及未成年人使用规则 → 再规划学生本人入口。  
  **业务价值：**建立独立的本人访问资格；P0不提供学生账号登录和本人查分，不能复用家长监护关系绕过。

- **学生请假、考勤与作业**  
  **适用角色：**学生、有效监护人、班主任、教务。  
  **操作流程：**后续分别确认请假审批、考勤来源与核实、作业布置与反馈规则 → 再安排独立流程。  
  **业务价值：**在身份与基础档案可靠后扩展家校服务，本期不交付。

## 4. 核心业务主流程

### 4.1 建档与关联

教务建立正式学生 → 校验全校唯一学号及必要资料 → 班主任收集监护人资料 → 校方后台核实对应关系 → 家长真实本人手机号验证 → 匹配激活 → 小程序选择本人有效关联孩子。遗漏先由校方补录再发定向、限时、一次有效邀请；手机号异常、关系争议和换微信必须经校方核实，处理与失效保留记录。学生毕业／离校即停止家长资料访问，历史内部保留。

### 4.2 成绩处理与查询

教务确定考试班级、科目满分与计分规则 → Excel导入 → 正式学生匹配与异常清单 → 处理异常 → 按考试＋班级发布 → 当前有效家长查询关联孩子分数历史 → 错误时撤回不可见 → 更正新版本发布。发布、撤回和更正在后台办理，小程序提供查询。任何未处理异常都不能跳过发布检查，总分不以不完整科目凑数。

### 4.3 家校通知与确认

发布人选学生形成范围快照 → 发布通知 → 以当前有效关系提供查看 → 每位家长分别记阅读与主动确认 → 主统计按学生至少一位当前有效监护人主动确认 → 发布人查看未确认学生并跟进。无有效家长的适用学生仍列为未确认并提示待核实关系，不从统计中静默删除；撤销已确认的关系后，旧回执保留历史但不再满足主统计，现关联家长须自己确认，失效家长不能继续访问。

### 4.4 核心验收场景

- 同名学生可区分，全校重复学号不能生效；转班、毕业或离校有记录，考试与通知历史不被重写。
- 一个家长关联两孩、一孩两家长分别生效；仅手输手机号、用另一微信身份、转发邀请、已过期或重复使用邀请均不能越权。漏名补录后正确激活，失效关系不能继续查看。
- 同一考试含真实0分、缺考、免考、未录入四类样例；未录入或未匹配等异常未处理时不能发布，应计科目不齐不显示总分。发布一个班不会开放其他未发布班级。
- 正式发布后当前有效家长可见关联孩子分数，撤回后不可见，更正后展示新版本；学生直接访问、普通访客和无相应授权员工均不可取得分数。关系失效或学生毕业／离校后家长不可继续访问，历史内部保留。
- 通知发布后转班不改变学生快照，关系变化按当前资格判断访问；两位家长各自阅读与主动确认，主统计按当前有效监护人至少一位主动确认的学生计一次。同家长两孩分别核查；已确认关系撤销后旧回执只留历史，不代替新关联家长确认。

## 5. 本期边界与不包含的功能

- 后台承担档案、核实、成绩导入处理发布、通知范围及回执核查；小程序承担当前有效家长的孩子查询与确认，P0无学生本人访问。Web门户继续公开信息与招生游园，App仍为P1移动办公。
- 本期仅建设最小正式学生档案，不声称已交付完整学籍、录取转学手续、排课、考试组织、教学或学习平台；预约学生姓名、光荣榜不能复用为正式档案。
- 不提供排名、等级、评语、综合画像、智能评价、家长查看全班分数或公开成绩榜。
- P1成绩疑问与同口径趋势、P2学生请假考勤作业均为后续范围。
- 学生毕业／离校即停止家长资料访问，历史由校方内部保留；校方核实责任岗位、手机号验证方式和试运行名单由学校在上线验收前确认，不能以待定参数绕过正式关系和发布规则。
