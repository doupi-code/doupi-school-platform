# 家校开放日送物预约

更新日期：2026-11-05。状态：已确认纳入P0首批开发，当前待开发、待实际业务验收。它是面向在校家庭的独立活动，不是现有招生游园预约的已实现能力。

## 1. 产品定位与核心价值

学校在指定校区、日期与时段开放在校家庭到访，家长提前登记适用孩子与实名到访人员，入校当面向孩子送物。学校根据接待容量控制人数，并留下预约、取消、停办、实际人员入校和可选离校记录。

活动依赖[正式学生档案与已核实监护关系](07-学生与家长在校服务.md)。入学前招生游园与在校开放日分别配置、预约、生成凭证和统计，不能用招生预约学生姓名证明在校资格。送物在指定区域当面交接，本期不接管物品物流或代收。

一场活动定义为单校区、单日期的一次开放安排，可以包含多个到校时段；跨校区或跨日必须分别建活动。同家长同活动只有一有效订单，多孩共用同一预约时段。家长可以参加另一日期或校区的其他活动，不能把“同活动一单”解释为全学期只能预约一次。

核心价值是让家庭知道何时、何地、由谁到访，避免多人重复为同一孩子占位，按实际到访人员而非孩子数控制学校总接待量，并对现场记录的准确边界作出清楚表达。

## 2. 用户角色与核心使用场景

### 2.1 学校活动管理人员

- 设置校区场次、开放日期时段、报名起止和取消截止，确认适用学生、交接区域与接待容量。
- 查看有效预约、取消、实际入校及已入校未登记离校人数，按授权查询明细。
- 处理活动停办与通知，核实补录现场记录并保留原预约和已发生历史。

### 2.2 家长／有效监护人

- 为本人关联的适用孩子预约，填写实名到访人员，同活动多孩合一单；在原订单追加孩子时沿用原时段与原实名人员名单。
- 查询本人订单与有效凭证；未入校且截止前可取消，需要改期时按风险提示取消后重约。
- 按学校要求到指定区域当面送物，可自报离校；发现其他监护人已为孩子预约时只获知该孩子已约。

### 2.3 现场工作人员

- 在授权活动与校区核对当前有效凭证和实际实名到访人员，可分批登记入校。
- 避免重复登记导致重复计人，拒绝将已取消或停办凭证当作有效入校安排。
- 按实际情况登记离校，或核实家长自报、事后补录并保留来源，不凭活动结束自动填出校。

## 3. 功能清单

### 3.1 P0 核心必做

- **OPEN-01 活动与校区场次配置（已确认待开发）**  
  **适用角色：**活动管理人员。  
  **操作流程：**创建独立家校开放日 → 设置校区、日期、时段、报名起止、取消截止、人数限额、每单人数上限、适用学生与交接区域 → 核对后开放。  
  **业务价值：**形成明确可执行的学校安排；与招生游园的开放规则、凭证和台账分开，未开始、已截止、满额和已停办均不能继续接受有效预约。

- **OPEN-02 监护资格、合单与实名人数占位（已确认待开发）**  
  **适用角色：**有效监护人。  
  **操作流程：**核验当前关系与孩子适用资格 → 选择孩子 → 同家长同活动多孩合并一单并共用同一时段 → 填写实名到访人员 → 校验每单上限和余量 → 有名额即预约成功；已有有效单可沿用原时段和完全相同实名人员名单追加适用且有效关联的孩子。  
  **业务价值：**无需招生式等待人工确认；按订单实名到访人员人数占位，孩子数不增加或减少占位，追加孩子也不额外占位。同一订单同一实名人员只计一次；一人去看多个孩子仍占一人。更换时段或增减更换访客的正式修改留P1，P0仅在符合取消条件时取消重约并提示名额风险。

- **OPEN-03 每孩子唯一预约与家庭隐私（已确认待开发）**  
  **适用角色：**有效监护人、授权活动管理人员。  
  **操作流程：**提交时校验同一孩子同一活动仅一有效单 → 两位家长同时提交时仅允许一单成功 → 其他监护人查询本人孩子时提示已约。  
  **业务价值：**防止同孩跨场次或跨监护人重复占位。其他监护人不因此获得订单详情、其他孩子、访客姓名或联系方式；同行人员不会取得正式学生资料和成绩查看权限。

- **OPEN-04 有效凭证、取消与停办（已确认待开发）**  
  **适用角色：**预约家长、活动管理人员。  
  **操作流程：**成功后查询有效凭证和交接指引 → 尚无人员入校且在取消截止前可取消整单并释放占位 → 学校停办时通知、使相关凭证失效并保留历史。  
  **业务价值：**取消结果与容量一致；只要订单已有人员入校，不能按未入校单自助取消。停办不删除已经发生的入校记录，未通知成功与已通知结果分别记录，不用失效凭证继续入校。

- **OPEN-05 实际人员入校登记（已确认待开发）**  
  **适用角色：**授权现场工作人员。  
  **操作流程：**核对活动、校区、有效订单与实名人员 → 勾选本批实际到访人员 → 登记办理人与入校时间 → 后续批次仅登记尚未入校人员。  
  **业务价值：**预约人数与实际入校人数分开；支持同单分批到达，重复扫码或重复登记不重复计人。未登记人员不能因同单其他人到达就被自动标为已入校。

- **OPEN-06 可选离校记录与统计（已确认待开发）**  
  **适用角色：**现场工作人员、预约家长、活动管理人员。  
  **操作流程：**工作人员登记／家长自报／校方核实补录 → 分别保留人员、时间、登记来源及办理依据 → 按人员核查台账。  
  **业务价值：**离校登记非强制。家长自报与工作人员登记、核实补录不得混写为同等核验事实；无离校记录不等于仍在校，活动结束不自动记已离校。统计称“已入校未登记离校人数”，不称实时在校人数；离校不释放本场预约总接待容量。

### 3.2 P1 重要迭代

- **开放日候补与正式改期**  
  **适用角色：**家长、活动管理人员。  
  **操作流程：**满额登记候补 → 按后续明确规则补位；正式改期核查目标场次容量后调整安排并同步凭证。  
  **业务价值：**减少重复抢名额与人工沟通。P0仅在符合取消规则时取消后重约，明确提示原名额释放、不保留、目标场次可能满额，不承诺无损改期。

### 3.3 P2 远期规划

- **与后续学生请假、考勤和作业服务衔接**  
  **适用角色：**学校管理人员、班主任、家长、学生。  
  **操作流程：**待后续各自业务规则确认 → 评估必要信息衔接 → 保留独立记录与授权。  
  **业务价值：**避免把一次开放日到访当作学生考勤或请假事实；本期不扩展这些服务。

## 4. 核心业务主流程

### 4.1 配置与预约

1. 学校配置独立活动，限定单校区单日期，可含多个到校时段；跨校区或跨日另建活动。明确报名起止、取消截止、接待人数、每单上限、适用学生与交接区域。
2. 家长以当前有效监护关系进入小程序，查看适用孩子和当前余量；不适用、关系失效或非在读孩子不能预约在读活动。
3. 同家长同活动仅一有效单，多孩共用同一时段，填写实名到访人员，按实际访客人数占位。已有单追加孩子必须保留原时段和完全相同的实名人员名单，仅追加仍有效关联、符合活动适用范围且未被其他有效单预约的孩子，原占位不增加。
4. 提交时同时校验报名窗口、容量、每单上限、孩子适用性与同活动唯一预约；任一条件不符明确失败且不占位，条件满足即成功并生成有效凭证。
5. 两位家长竞争同一孩子或多人竞争最后名额时只能产生符合限额的成功结果，失败者不能持有效凭证或留下重复占位。其他监护人仅获知本人孩子已约，不泄露该单其他信息。

### 4.2 取消、重约与停办

1. 订单无人入校且仍在取消截止前，家长可取消整单，凭证失效并释放全部预约人数；已过截止或已有人员入校，不能按该规则取消。
2. P0需要改期时先明确提示风险，再由家长取消后另行预约；新场次余量不保证，原场次名额不保留。同一孩子旧单仍有效时不能新增第二有效单。
3. 学校停办活动或场次时通知受影响家长，所有相关入校凭证失效；预约与现场历史保留，不抹去已入校事实。停办后的状态与取消区分。

### 4.3 到校当面送物与离校

1. 家长按校区、日期时段和区域指引到校，工作人员核验当前有效凭证及本批实际实名人员。
2. 分批登记入校，逐人保留入校时间与办理人；重复核验不增加实际入校人数，也不自动带入未到同行人员。
3. 家长与孩子在指定区域当面交接物品，平台不登记成物品代收或物流签收。
4. 离校可由工作人员登记、家长自报或校方核实补录，逐人记录来源与时间。登记不是强制出校机制，无记录不证明人仍在校。
5. 活动结束仅结束活动可办理时段，不自动将未登记者改为已离校；离校不重新开放已消耗的本场总接待容量。

### 4.4 核心验收场景

- **配置与报名窗口**：未开始、已截止、满额、停办、错误校区或不适用学生无法成功；有名额且满足规则时立即成功，不进入招生待确认流程。
- **按人计数与合单**：一位家长看两个孩子、两位到访人员只占2人；同家长同活动合一单且同一时段，同单重复人员不重复计数，超过每单上限失败。原单追加适用关联孩子时不增加占位，原时段和实名人员名单改变则不能作为追加；另一校区或另一日期活动可另约。
- **竞争与隐私**：同孩两家长同时提交仅一方成功；同孩跨场次仍不能有第二有效单；另一个监护人只知本人孩子已约，不能取得订单其他孩子或访客资料。
- **取消与改期**：未入校且截止前取消释放名额，重复取消不重复释放；过截止或任一人员已入校不得按未入校规则取消；取消重约前明确名额不保证。
- **分批入校与重复登记**：3人订单先到1人后到2人分别登记，实际入校依次为1、3，重复操作仍为3；无效凭证和未入校人员不计入。
- **离校记录与统计**：分别验证工作人员、家长自报、核实补录来源；未登记离校不显示“仍在校”，结束不自动填离校，指标名为“已入校未登记离校人数”，离校不释放接待容量。
- **停办与资格**：停办通知与凭证失效生效，原预约和已入校历史仍可按权限核查；失效监护关系与同行访客不能获取学生档案或成绩。

## 5. 本期边界与不包含的功能

- 小程序承载家长预约、本人订单、凭证、取消与可选离校自报；后台承载活动配置、名单核查、停办、现场台账与授权补录；授权现场工作人员可使用小程序现场入口。员工权限独立核实，不由家长资格或同行身份授予。
- 仅限学校指定开放日入校当面送物，不包含物品代收、保管、寄存、物流配送、物品签收、丢损理赔或支付。
- 不包含硬件门禁、人脸识别、定位追踪、强制出校登记或实时在校人数判断。
- P0允许沿用原时段、原实名人员名单追加适用关联孩子；不包含候补、正式改期、预约拆单、访客修改或任意时段自由入校。候补与正式改期为P1，更换时段或访客时P0仅符合条件后取消重约，名额不保证。
- 招生游园、学生请假、考勤和作业各有独立范围，开放日的预约与出入记录不能替代这些业务事实。
