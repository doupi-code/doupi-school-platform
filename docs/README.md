更新日期：2026-11-06。产品方向：以学校行政办公为基础，小程序首批扩展在校家长的成绩、通知与开放日送物服务；四端规划完整覆盖，App功能仍按P1迭代。

## 阅读顺序

1. 阅读[产品规划](product/01-产品规划.md)，了解产品定位、用户场景、功能优先级、核心流程和本期边界。
2. 阅读[角色与权限](product/02-角色与权限.md)及[现状与版本范围](product/03-现状与版本范围.md)，区分已有能力、本期目标和后续规划。
3. 阅读[全端功能与协同矩阵](product/ends/00-全端功能与协同矩阵.md)，明确管理后台、Web门户、微信小程序与App的用户和职责。
4. 按工作职责查阅下方功能文档，确认操作、规则与异常处理。
5. 依据[验收标准](product/04-验收标准.md)检查是否达到交付要求。
6. 按根目录[开发计划与排期](../开发计划.md)进入各端模块的接口、字段流转、DDL、实现骨架和异常处理；排期以1名Java开发结合AI辅助估算。

## 维护规则

- 产品方向与优先级在产品规划中维护；功能细节在对应功能文档维护；验收场景在功能文档与统一验收清单中对应。
- 当前行为与目标行为分别标注；“已有能力”仅表示仓库内容有对应支持，线上可用性须另行验收。
- 文档变更同步更新导航和相关引用，不重复创建同一功能的修复说明。
- 业务规则变化时同步核对角色、流程、库存口径、报表和验收条件。
- 阶段性执行流水不作为长期产品文档；保留仍有约束力的决策、限制和未解决问题。
- 不保存密码、令牌、密钥或个人本地路径；涉及运行环境的信息以实际维护配置为准。
