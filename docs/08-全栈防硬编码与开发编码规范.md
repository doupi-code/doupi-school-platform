# 08 - 全栈防硬编码与开发编码规范

## 1. 核心红线准则

为保证多端系统在生产、测试、本地开发各环境间平滑流转，杜绝因环境变化导致线上故障，全体开发者必须严格遵守以下防硬编码红线：

### 1.1 严禁硬编码网络地址与凭据
- ❌ **严禁在前端代码中硬编码任何具体 IP 或端口**（如 `http://101.43.58.160:8088`、`http://localhost:8080`）。所有请求必须统一走相对路径（如 `/prod-api/`、`/api/`），由前端构建环境变量或 Nginx 网关反向代理分发。
- ❌ **严禁在代码中硬编码生产数据库密码、Redis 强密码或云端私钥**。所有凭据通过系统环境变量或 JVM 启动参数传参注入。

### 1.2 严禁硬编码业务实体数据
- ❌ **严禁在前端代码中假写静态列表代替真实业务**（如硬编码写死班级、教师列表、库存物资）。
- ✅ **动态数据原则**：所有业务展示必须对接后端 API，支持后台管理员增删改查实时联动；前端仅保留结构定义与空状态/网络异常时的离线兜底机制。

---

## 2. 自动化防硬编码审计工具

项目内置了工程级的防硬编码自动化检测脚本，可在提交代码前一键扫描全部前端与后端源码：

```bash
# 运行工程完整性与硬编码扫描
node scripts/check-hardcoding.mjs
```

### 扫描检测项覆盖：
1. **网络敏感检测**：扫描是否包含写死的公网 IP、非标准内网端口（如 `:8080`、`:8088`）。
2. **凭据安全检测**：扫描是否包含明显的 Token、Key、Password 字符串常量。
3. **残留名称审计**：检测是否意外遗留了废弃的旧框架名称或旧工程代号。
