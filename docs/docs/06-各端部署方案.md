## 一、服务器资源规划

### 1.1 内存分配策略

> [!CAUTION]
> 4GB 内存是**刚好够用**的底线配置。必须精细化分配，任何一个组件多吃 200MB 都可能导致 OOM。

```
总内存: 4096 MB
┌─────────────────────────────────────────────────┐
│  OS + 系统开销          ≈ 400 MB                │
│  MySQL 8.0 (Docker)     ≈ 600 MB (严格限制)     │
│  Redis 7.0 (Docker)     ≈ 128 MB (maxmemory)    │
│  Java 应用 (JVM)        ≈ 2048 MB (-Xmx2g)      │
│  Nginx + 静态文件缓存   ≈ 100 MB                │
│  预留缓冲                ≈ 820 MB                │
└─────────────────────────────────────────────────┘
```

### 1.2 磁盘规划（40-60GB SSD）

| 用途 | 空间 |
|:--|:--|
| OS + Docker 引擎 | ~8 GB |
| MySQL 数据目录 | ~5 GB（预估 3 年数据量） |
| Redis RDB/AOF | ~1 GB |
| Java 应用 JAR + 依赖 | ~500 MB |
| Nginx + 前端静态文件 | ~200 MB |
| 上传文件存储 | ~10 GB |
| Docker 镜像缓存 | ~5 GB |
| 日志文件 | ~5 GB（需配置轮转） |
| **剩余可用** | **~10-25 GB** |

## 二、部署架构

### 2.1 单机 Docker Compose 架构

```
                    Internet
                       │
                       ▼
              ┌──────────────────┐
              │   Nginx (:443)   │  ← SSL 终止 + 反向代理
              │   (:80→443重定向) │
              └────┬───┬───┬─────┘
                   │   │   │
        ┌──────────┘   │   └──────────┐
        ▼              ▼              ▼
   /admin/*      /api/*          /client/*
   React管理端   Java后端         React用户端
   (静态文件)    (:8080)         (静态文件)
                   │
              ┌────┴────┐
              ▼         ▼
         MySQL(:13306) Redis(:6379)
         (Docker)      (Docker)
```

### 2.2 Docker Compose 配置

```yaml
# docker-compose.production.yml
version: '3.8'

services:
  # ---- 数据层 ----
  mysql:
    image: mysql:8.0
    container_name: doupi-mysql
    restart: always
    ports:
      - "13306:3306"
    environment:
      MYSQL_ROOT_PASSWORD: ${MYSQL_ROOT_PASSWORD}
      MYSQL_DATABASE: doupi
      MYSQL_USER: doupi_app
      MYSQL_PASSWORD: ${MYSQL_APP_PASSWORD}
    volumes:
      - mysql-data:/var/lib/mysql
      - ./sql/init:/docker-entrypoint-initdb.d
    command: >
      --character-set-server=utf8mb4
      --collation-server=utf8mb4_unicode_ci
      --innodb-buffer-pool-size=384M
      --max-connections=200
      --slow-query-log=ON
      --long-query-time=1
    deploy:
      resources:
        limits:
          memory: 600M

  redis:
    image: redis:7.0-alpine
    container_name: doupi-redis
    restart: always
    ports:
      - "6379:6379"
    command: >
      redis-server
      --requirepass ${REDIS_PASSWORD}
      --maxmemory 128mb
      --maxmemory-policy allkeys-lru
      --save 900 1
      --save 300 10
    volumes:
      - redis-data:/data
    deploy:
      resources:
        limits:
          memory: 150M

  # ---- 应用层 ----
  app:
    image: doupi-server:latest
    container_name: doupi-app
    restart: always
    ports:
      - "8080:8080"
    environment:
      SPRING_PROFILES_ACTIVE: prod
      JAVA_OPTS: >
        -server
        -Xms1536m -Xmx2048m
        -Xmn768m
        -XX:+UseG1GC
        -XX:MaxGCPauseMillis=200
        -XX:+HeapDumpOnOutOfMemoryError
        -XX:HeapDumpPath=/logs/heapdump.hprof
        -Dfile.encoding=UTF-8
    volumes:
      - app-logs:/logs
      - upload-files:/upload
    depends_on:
      - mysql
      - redis
    deploy:
      resources:
        limits:
          memory: 2200M

  # ---- 反向代理 ----
  nginx:
    image: nginx:1.25-alpine
    container_name: doupi-nginx
    restart: always
    ports:
      - "80:80"
      - "443:443"
    volumes:
      - ./nginx/nginx.conf:/etc/nginx/nginx.conf:ro
      - ./nginx/conf.d:/etc/nginx/conf.d:ro
      - ./web-admin/dist:/usr/share/nginx/html/admin:ro
      - ./web-client/dist:/usr/share/nginx/html/client:ro
      - ./certbot/conf:/etc/letsencrypt:ro
      - nginx-logs:/var/log/nginx
    depends_on:
      - app
    deploy:
      resources:
        limits:
          memory: 100M

volumes:
  mysql-data:
  redis-data:
  app-logs:
  upload-files:
  nginx-logs:
```

## 三、Nginx 配置

### 3.1 主配置 (`nginx.conf`)

```nginx
worker_processes auto;
worker_rlimit_nofile 65535;

events {
    worker_connections 2048;
    use epoll;
}

http {
    include       mime.types;
    default_type  application/octet-stream;
    
    sendfile on;
    tcp_nopush on;
    keepalive_timeout 65;
    
    # Gzip 压缩（3-5Mbps 带宽下极为重要）
    gzip on;
    gzip_min_length 1024;
    gzip_comp_level 5;
    gzip_types text/plain text/css application/json application/javascript 
               text/xml application/xml image/svg+xml;
    gzip_vary on;

    # 上传文件大小限制
    client_max_body_size 20m;

    include conf.d/*.conf;
}
```

### 3.2 站点配置 (`conf.d/doupi.conf`)

```nginx
# HTTP → HTTPS 重定向
server {
    listen 80;
    server_name your-domain.com;
    return 301 https://$host$request_uri;
}

server {
    listen 443 ssl http2;
    server_name your-domain.com;

    # SSL 证书
    ssl_certificate     /etc/letsencrypt/live/your-domain.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/your-domain.com/privkey.pem;
    ssl_protocols TLSv1.2 TLSv1.3;

    # ---- Web 管理端 ----
    location /admin {
        alias /usr/share/nginx/html/admin;
        try_files $uri $uri/ /admin/index.html;
        
        # 静态资源长缓存
        location ~* \.(js|css|png|jpg|gif|ico|woff2)$ {
            expires 30d;
            add_header Cache-Control "public, immutable";
        }
    }

    # ---- Web 用户端（官网首页）----
    location / {
        root /usr/share/nginx/html/client;
        try_files $uri $uri/ /index.html;
        
        location ~* \.(js|css|png|jpg|gif|ico|woff2)$ {
            expires 30d;
            add_header Cache-Control "public, immutable";
        }
    }

    # ---- API 反向代理 ----
    location /api/ {
        proxy_pass http://app:8080/api/;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        
        # SSE 大屏实时推送支持
        proxy_buffering off;
        proxy_cache off;
        proxy_read_timeout 600s;
    }

    # ---- 微信小程序 API ----
    location /api/wx/ {
        proxy_pass http://app:8080/api/wx/;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    }

    # ---- 文件上传/下载 ----
    location /profile/ {
        proxy_pass http://app:8080/profile/;
    }
}
```

## 五、自动部署脚本

### 5.1 一键部署脚本 (`deploy.sh`)

```bash
#!/bin/bash
set -e

echo "===== 豆皮系统部署 ====="

# 1. 拉取最新代码
cd /opt/doupi
git pull origin main

# 2. 构建后端 JAR
cd doupi-server
mvn clean package -DskipTests -Pprod
docker build -t doupi-server:latest .

# 3. 构建前端（管理端）
cd ../doupi-web-admin-react
npm ci && npm run build
rm -rf ../deploy/web-admin/dist
cp -r dist ../deploy/web-admin/

# 4. 构建前端（用户端）
cd ../doupi-web-client-react
npm ci && npm run build
rm -rf ../deploy/web-client/dist
cp -r dist ../deploy/web-client/

# 5. 重启服务
cd ../deploy
docker compose -f docker-compose.production.yml up -d --force-recreate app nginx

echo "===== 部署完成 ====="
```

### 5.2 后端 Dockerfile

```dockerfile
FROM eclipse-temurin:17-jre-alpine
LABEL maintainer="doupi"

WORKDIR /app
COPY doupi-admin/target/doupi-admin.jar app.jar

# 健康检查
HEALTHCHECK --interval=30s --timeout=5s \
  CMD wget -qO- http://localhost:8080/actuator/health || exit 1

ENTRYPOINT ["sh", "-c", "java $JAVA_OPTS -jar app.jar"]
```

## 六、JVM 调优（4 核 4G 专项）

```bash
# 生产环境 JVM 参数
JAVA_OPTS="
  -server
  -Xms1536m                    # 初始堆 1.5G
  -Xmx2048m                    # 最大堆 2G
  -Xmn768m                     # 新生代 768M
  -XX:+UseG1GC                 # G1 垃圾回收器
  -XX:MaxGCPauseMillis=200     # 最大停顿 200ms
  -XX:G1HeapRegionSize=8m      # G1 Region 大小
  -XX:+HeapDumpOnOutOfMemoryError
  -XX:HeapDumpPath=/logs/heapdump.hprof
  -XX:+PrintGCDetails          # GC 日志（排障用）
  -Xloggc:/logs/gc.log
"
```

> [!WARNING]
> 如果 OCR 推理（ONNX 模型）导致内存压力过大，考虑将 `-Xmx` 降为 `1536m` 并增加 `-XX:MaxDirectMemorySize=256m`。

## 七、监控与告警

### 7.1 轻量监控方案（适合 4G 服务器）

> [!TIP]
> 不部署 Prometheus + Grafana（太耗资源）。使用云平台自带监控 + 简单脚本告警。

```bash
# monitor.sh — 每 5 分钟由 crontab 调用
#!/bin/bash

# 检查 Java 进程
if ! docker ps | grep -q doupi-app; then
  echo "Java 应用已停止！" | mail -s "告警：豆皮系统宕机" admin@example.com
  docker compose -f docker-compose.production.yml restart app
fi

# 检查内存使用（超过 90% 告警）
MEM_USAGE=$(free | awk '/Mem/{printf "%.0f", $3/$2*100}')
if [ "$MEM_USAGE" -gt 90 ]; then
  echo "内存使用率 ${MEM_USAGE}%" | mail -s "告警：内存不足" admin@example.com
fi

# 检查磁盘使用
DISK_USAGE=$(df / | awk 'NR==2{print $5}' | tr -d '%')
if [ "$DISK_USAGE" -gt 85 ]; then
  echo "磁盘使用率 ${DISK_USAGE}%" | mail -s "告警：磁盘不足" admin@example.com
fi
```

## 八、备份策略

```bash
# backup.sh — 每日凌晨 2 点执行
#!/bin/bash
BACKUP_DIR=/opt/doupi/backups
DATE=$(date +%Y%m%d)

# MySQL 备份
docker exec doupi-mysql mysqldump -u root -p${MYSQL_ROOT_PASSWORD} doupi | gzip > ${BACKUP_DIR}/mysql_${DATE}.sql.gz

# Redis 备份
docker exec doupi-redis redis-cli -a ${REDIS_PASSWORD} BGSAVE
cp /opt/doupi/deploy/redis-data/dump.rdb ${BACKUP_DIR}/redis_${DATE}.rdb

# 上传文件备份
tar czf ${BACKUP_DIR}/uploads_${DATE}.tar.gz /opt/doupi/deploy/upload-files/

# 保留最近 30 天备份
find ${BACKUP_DIR} -mtime +30 -delete

echo "备份完成: ${DATE}"
```

## 九、带宽优化（3-5 Mbps 专项）

> [!IMPORTANT]
> 3-5 Mbps 约等于 **375-625 KB/s**，属于低带宽场景。

| 优化措施 | 预期效果 |
|:--|:--|
| **Nginx Gzip 压缩** (level 5) | JS/CSS 体积减少 60-70% |
| **静态资源长缓存** (30 天 + immutable) | 回访用户零带宽消耗 |
| **图片压缩** (WebP 格式 + 质量 80%) | 图片体积减少 50%+ |
| **CDN 加速** (可选，阿里云/腾讯云 CDN) | 静态资源由 CDN 分发 |
| **API 响应压缩** (Spring Boot gzip) | 接口响应体积减少 50%+ |
| **前端代码分割** (Vite code splitting) | 首屏只加载必要 JS |
| **大屏图片懒加载** | 减少首屏请求数 |
