## 二、防硬编码四大铁律（绝对禁止与强制合规）

### 铁律 1：【实体与 DTO 零初值原则】严禁在 POJO 声明时赋予默认值

#### 🚫 违规反例（曾引发重大漏算灾难）
```java
// 错误写法：在实体属性上直接赋初值
public class EduPrintRecord extends BaseEntity {
    private Long pageCount = 1L;     // ❌ 严禁赋默认值！
    private String printSide = "1";   // ❌ 严禁赋默认值！会导致 GET 查询默认只查单面印刷，过滤掉所有双面印刷！
}
```

#### ✅ 合规做法
```java
// 正确写法：实体属性保持纯净，绝不设置默认值
public class EduPrintRecord extends BaseEntity {
    private Long pageCount;
    private String printSide;
}
```

#### 📌 规则要点：
1. **GET 查询对象反序列化**：Spring MVC 将请求 Query 参数反射组装为 Entity/DTO 时，若无请求参数传入，对象保留的是类字段的默认初值；
2. **MyBatis 动态 SQL 误判**：`<if test="printSide != null and printSide != ''">` 会因默认初值判定为 true，导致 SQL 隐式被拼入无意图的过滤条件，造成查询结果严重失真；
3. **Getter 方法必须 100% 纯净取值**：**严禁在 getter 方法中编写任何三元兜底默认值**（如 `return printSide != null ? printSide : "1";`）。因为 MyBatis OGNL 判空实际是通过反射调用 `getPrintSide()`！若 getter 返回了兜底值 `"1"`，MyBatis 同样判定为非 null 并强行拼接过滤条件，引发极难排查的“幽灵过滤”重大 Bug；
4. **新增默认值处理**：新增记录若有默认业务值，必须在 **数据库表结构（DEFAULT 约束）** 或 **Service 业务逻辑层（显式判空赋予）** 中执行，绝对禁止留在 Entity 字段定义或 getter 方法上。

### 铁律 2：【业务魔数与费率参数化原则】严禁在代码中写死业务计算数值

#### 🚫 违规反例
```java
// 后端 Java 错误写法：写死单价 0.06、写死每包 500 张
double reams = Math.round((completedPages / 500.0) * 10.0) / 10.0;
double totalCost = Math.round(completedPages * 0.06 * 100.0) / 100.0;
```
```typescript
// 前端 TSX 错误写法：在表格和卡片中到处写死公式
const cost = (Number(totalPages) * 0.06).toFixed(2);
<span>折合标准用纸: {(displayPages / 500).toFixed(1)} 包 (500张/包)</span>
```

#### ✅ 合规做法
1. **统一纳入系统参数表 `sys_config`**：
   - 纸张折合单价：`edu.print.paperPricePerSheet`（默认 `0.06`）
   - 每包标准纸张张数：`edu.print.sheetsPerReam`（默认 `500`）
2. **后端通过 `ISysConfigService` 动态读取并统一计算输出**：
   ```java
   String priceConfig = configService.selectConfigByKey("edu.print.paperPricePerSheet");
   double unitPrice = StringUtils.isNotEmpty(priceConfig) ? Double.parseDouble(priceConfig) : 0.06;
   
   String reamConfig = configService.selectConfigByKey("edu.print.sheetsPerReam");
   double sheetsPerReam = StringUtils.isNotEmpty(reamConfig) ? Double.parseDouble(reamConfig) : 500.0;
   
   double totalCost = Math.round(completedPages * unitPrice * 100.0) / 100.0;
   double reams = Math.round((completedPages / sheetsPerReam) * 10.0) / 10.0;
   ```
3. **前端直接消费后端结算结果**：
   前端在明细表与看板中直接展示接口返回的 `record.cost`、`summary.totalCost`、`summary.totalReams`，绝不自行硬编码单价自算。

### 铁律 3：【字典项与选项全端协同原则】严禁在前端表单写死 Option

#### 🚫 违规反例
```tsx
// 错误写法：在表单和筛选中写死静态 Option
<Select placeholder="请选择年级">
  <Option value="高一">高一</Option>
  <Option value="高二">高二</Option>
  <Option value="高三">高三</Option>
</Select>

<Select placeholder="请选择纸张规格">
  <Option value="A4">A4 纸</Option>
  <Option value="8K">8K 纸</Option>
</Select>
```

#### ✅ 合规做法
1. **系统数据字典统一收敛**：
   - 年级字典：`edu_grade_type`（高一、高二、高三、高中部、复读部、初中部等）
   - 纸张类型：`edu_paper_type`（A4、A3、8K、16K、B5 等）
   - 物资分类：`stock_goods_category`（教师办公品、学生教材、文印耗材等）
2. **前端统一使用字典钩子/接口动态渲染**：
   ```tsx
   import { useDict } from '@/api/system/dict';
   
   const { edu_grade_type, edu_paper_type } = useDict('edu_grade_type', 'edu_paper_type');
   
   <Select 
     placeholder="全部年级" 
     allowClear
     options={edu_grade_type.map(d => ({ label: d.dictLabel, value: d.dictValue }))} 
   />
   ```
3. **后端严禁在代码中写死判断**：
   - 严禁：`public static final String[] GRADES = {"高一", "高二", ...};`
   - 合规：从字典缓存 `DictUtils.getDictCache("edu_grade_type")` 读取或校验有效性。

## 三、各端工程化开发实操指引

### 3.1 Java 后端规约清单
1. **Controller 层**：
   - 接收参数的查询对象，禁止包含初值；
   - 分页参数必须使用 `startPage()`，严禁在业务 SQL 中硬编码 `LIMIT 0, 10`；
2. **Service 业务层**：
   - 涉及金额、税率、费率、包装换算，必须调用 `sysConfigService.selectConfigByKey(...)`；
   - 提取参数时设置容错默认值（Fallback），保证配置表缺省时平滑向下兼容；
3. **Mapper XML 层**：
   - 动态 SQL 中对可空状态字段严格使用 `<if test="status != null and status != ''">`；
   - 排除逻辑必须具有显式业务意图声明（如 `params.excludeCancelled == 'true'`），不可做暗箱操作。

### 3.2 React 管理端规约清单
1. **单文件代码量控制**：单个页面 TSX 原则上不超过 500 行，复杂子组件、详情弹窗、图表配置必须拆分到单独文件；
2. **数值与单位格式化**：
   - 纸张数量：`Number(val).toLocaleString()`；
   - 金额成本：`¥ ${Number(val).toFixed(2)}`；
   - 统一使用 `Table.Summary` 展示台账表底小计与合计，保持表底与卡片 100% 对齐；
3. **严禁在页面中写死权限 ID 与角色 Key**：使用权限指令 `@ss.hasPermi('...')` 及前端 `hasPermi` 函数。

### 3.3 门户端与移动端规约清单
1. **门户端组件无状态渲染**：
   - 所有资讯分类、校区列表、热线电话均通过 API 获取，本地仅保留网络异常情况下的 `fallback` 数据，并提供 `isFallback` 状态提示；
2. **小程序网络层统一拦截**：
   - 所有请求必须经过统一的 `request.js`，包含 Token 自动附加、统一 401 拦截处理、网络异常重试机制。

## 四、自动化检测与持续保障机制

1. **静态扫描与脚本检测**：
   - 项目提供 `scripts/check-hardcoding.ps1` 自动化扫描脚本；
   - 纳入每次代码提交（Git pre-commit Hook）与持续集成流水线；
2. **违规处罚与评审**：
   - PR 审查中一旦发现 POJO 默认值、魔数费率或写死 Option，一律拒绝合并（Reject PR）；
   - 定期对 `sys_config` 与 `sys_dict_data` 进行全库完整性核对。
