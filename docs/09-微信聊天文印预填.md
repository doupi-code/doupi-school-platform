# 微信聊天文印预填

## 使用流程

在文印登记页面粘贴多天微信消息，先查看候选列表，再逐条填写并保存。右侧默认展示当前任务所在日期的**全部聊天消息**，蓝色突出该任务的材料和打印指令；可展开本次全部消息。时间不明确时保留原文，不猜日期。

缺附件、附件过期、上传失败、只有材料或只有要求，都保留候选。未知份数、页数、单双面、纸张等留空；昵称不自动等同于教师档案。选择教师后应用到本次同一发送人的候选。关联存在歧义或疑似重复时须对照原文确认。

保存成功自动进入下一条，失败保留当前输入。候选切换保留本会话草稿；导入与保存互斥以免响应覆盖队列。关闭浏览器后的会话恢复不在本次范围内。

## 模块与契约

- `doupi-server/doupi-edu`：`ChatMessageNormalizer`保留发送人、时间、正文及顺序；`ChatPrefillParser`按发送人和日期绑定指令，产生候选及字段证据。`EduOcrServiceImpl`同时承接文本和截图入口，历史同名只提示，不自动跳过。
- `doupi-web-admin-react/src/pages/edu/record`：`chatPrefill.ts`提供类型、剪贴板规范化、附件匹配和会话合并；`ChatCandidateList`展示候选；`ChatSourcePanel`展示当天全部消息；原登记页面协调单条表单与保存。
- `text-parse`和`ocr-parse`的原路由保持不变。返回增加`messages`，候选增加`taskId`、`sender`、`sourceMessageIds`、`fieldEvidence`、`reviewReasons`及`attachmentStatus`。未知数字为空，前端不补默认值。
- 实际附件只在文件名唯一匹配时自动关联；多个同名候选或附件交给用户选择。PDF/Word解析出的页数可补空缺；Excel工作表数不当作打印页数。聊天明确页码范围优先于附件完整页数。
- 解析、预览及编辑不产生出库；保存继续使用既有登记事务及权限。未改库存规则或数据库结构。

## 回归验证

后端（仓库根目录）：

```powershell
mvn -f doupi-server/pom.xml -pl doupi-edu -am test
```

前端（管理端目录）：

```powershell
node --test tests/chatPrefill.test.ts
npm run build
```

浏览器集成验证先启动管理端Vite到`127.0.0.1:5186`，再运行`node tests/chat-prefill.browser.cjs`。测试需要Playwright及浏览器；可用`PLAYWRIGHT_MODULE`指定能解析playwright的package.json路径，用`TEST_BROWSER`指定浏览器可执行文件，用`TEST_URL`覆盖本机地址。所有业务API均模拟，不写数据库。测试HTML不进入生产构建。

覆盖：完整洛卡记录26份材料、纯时间记录、无文件请求、前置多条说明、同名跨天、局部页数/彩色、HTML粘贴、当天全部消息、草稿恢复、候选预览取消、延迟图片隔离、上传失败保留及保存失败重试。

## 已知边界

规则只给有证据的数据或标记明确的关联建议，不能理解所有自然语言。若微信未向浏览器提供文字或HTML，网页无法恢复未传入的过期消息；此时只保留取得的文件候选，供用户手填。真实微信私有剪贴板格式仍需在用户电脑上用实际复制路径验收，浏览器自动测试仅覆盖标准剪贴板格式。
