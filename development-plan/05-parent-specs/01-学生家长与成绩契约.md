## 1. 统一标识与生命周期

正式学生与招生预约完全分离。`edu_student.student_no` 全校唯一且区分大小写；校区复用 `doupi_recruit_campus.campus_id VARCHAR(32)`，班级复用 `edu_class.class_id BIGINT`，现有班级没有校区字段，学生校区由校方核实维护。BIGINT 在 JSON 一律十进制字符串；版本号是非负 JSON 整数；UTC 存储 DATETIME(3)，ISO-8601 `Z` 出参，小程序显示 Asia/Shanghai。

最小共享表：`edu_student(student_id,student_no,student_name,campus_id,class_id,entry_year,status,version)`；`edu_guardian(guardian_id,guardian_name,phone_e164,status,version)`；`edu_student_guardian(link_id,student_id,guardian_id,relation,status,verified_by,verified_at,version)`；`edu_guardian_identity(identity_binding_id,guardian_id,identity_id,status,phone_verified_at,verification_method,version)`。完整 DDL 在 ADM-19 与 MINI-07；四表均有 created_at/updated_at/created_by/updated_by。学校核实关系是 VERIFIED，撤销 REVOKED；学生 ACTIVE 才有家长读权限，GRADUATED/LEFT/DISABLED 的内部记录保留。

一位家长可关联多孩子，一孩可有多位家长；一个家长当前最多绑定一个微信身份，一个微信当前最多激活一个家长档案。手机号是学校维护的家长标识，规范为中国大陆 `+86` 加 11 位手机号；不接受客户端手输手机号作为授权证据。微信已认证 identity 与员工 `kind`/员工绑定相互独立，不新增 JWT PARENT kind、不修改员工权限。所有 `/api/v1/parent/**` 以服务端 `Actors.current().identityId()` 实时检查四表；切换孩子只是 UI 选择，不产生新的权限或长期授权缓存。

主路径是学校先收集家长姓名、真实手机号、关系并核实，家长微信手机号能力由后端换取真实号码、精确匹配学校已核实档案后激活，无需逐人先发邀请。补漏或微信手机号能力不可用时，学校核对监护关系、手机号及微信归属后发指定 identity 的一次性24小时 MANUAL 邀请，记录核实依据编号，家长只消费指定自己的邀请。禁止根据姓名、预约记录、手机输入或已有员工身份自动授予。误绑、换号、换微信由学校先撤销旧绑定、核实新档案再发新邀请，绝不抢占仍有效绑定。

通知与开放日可保存 `student_id`、`link_id`、`identity_id` 作为投递目标，读取或报名时仍实时检查有效关系；禁用关系立即阻断新读取，缓存只放公开字典，不缓存家长资格和成绩。不得把手机号、分数、导入正文或邀请凭据写入业务请求日志。

## 2. 可供其他模块直接引用的授权类

未来文件 `backend/src/main/java/com/doupi/planref/parent/ParentAccess.java`；返回 student 的最小字段均为字符串，拒绝时统一 404 隐藏跨孩子标识。没有孩子返回空列表，可展示“请联系班主任核实关联”，不创建默认孩子。此类不要求 STAFF，也不修改 Actor.kind。

```java
package com.doupi.planref.parent;
import com.doupi.planref.*;
import java.util.*;
import org.springframework.stereotype.Service;
@Service
public class ParentAccess {
    private final Db db;
    public ParentAccess(Db db) { this.db = db; }
    private long identity() {
        long id = Actors.current().identityId();
        if (id <= 0) throw new Problem(401,"IDENTITY_REQUIRED","请先微信登录");
        return id;
    }
    public List<Long> studentIds() {
        return db.list("SELECT DISTINCT s.student_id FROM edu_student s "
            + "JOIN edu_student_guardian l ON l.student_id=s.student_id AND l.status='VERIFIED' "
            + "JOIN edu_guardian g ON g.guardian_id=l.guardian_id AND g.status='ACTIVE' "
            + "JOIN edu_guardian_identity b ON b.guardian_id=g.guardian_id AND b.status='ACTIVE' "
            + "WHERE b.identity_id=#{p.identity} AND s.status='ACTIVE' ORDER BY s.student_id",
            P.of("identity",identity())).stream().map(r -> Inputs.number(r.get("student_id"))).toList();
    }
    public void requireStudent(long studentId) { student(studentId); }
    public Map<String,Object> student(long studentId) {
        Map<String,Object> r = db.one("SELECT s.student_id,s.student_no,s.student_name,s.campus_id,s.class_id,c.class_name "
            + "FROM edu_student s JOIN edu_class c ON c.class_id=s.class_id "
            + "WHERE s.student_id=#{p.student} AND s.status='ACTIVE' AND EXISTS ("
            + "SELECT 1 FROM edu_student_guardian l JOIN edu_guardian g ON g.guardian_id=l.guardian_id "
            + "JOIN edu_guardian_identity b ON b.guardian_id=g.guardian_id "
            + "WHERE l.student_id=s.student_id AND l.status='VERIFIED' AND g.status='ACTIVE' "
            + "AND b.status='ACTIVE' AND b.identity_id=#{p.identity})",
            P.of("student",studentId,"identity",identity()));
        if (r.isEmpty()) throw new Problem(404,"STUDENT_NOT_ACCESSIBLE","孩子不存在或关联已失效");
        r.put("student_id",String.valueOf(r.get("student_id")));
        r.put("class_id",String.valueOf(r.get("class_id")));
        return r;
    }
}
```

## 3. 非 office_request 命令契约

不拿 `Commands.run` 的审批根冒充学生、考试。以下完整组件使用既有 `channel_idempotency`，scope_key 由认证 Actor 派生：STAFF 使用 `STAFF:<userId>`，其他使用 `EXTERNAL:<identityId>`，支持 identityId=0 的后台员工会话；action_code 由各 Service 固定。payload 必须含目标 ID、expectedVersion、完整业务正文，原始成绩/手机号正文只参与 SHA256 不入结果或日志。重放查询在业务版本校验前；同键异摘要 409；失败事务回滚占键；成功结果与业务同事务保存。各 Service 的 public 方法添加 `@Transactional`，调用组件前检查 STAFF 权限，事务中 scope SQL 再检查目标。

未来文件 `ParentCommands.java`：

```java
package com.doupi.planref.parent;
import com.doupi.planref.*;
import java.util.*;
import java.util.function.Supplier;
import org.springframework.stereotype.Component;
@Component
public class ParentCommands {
    private final Db db;
    public ParentCommands(Db db) { this.db=db; }
    public Map<String,Object> run(String action,String key,Map<String,Object> body,Supplier<Map<String,Object>> work) {
        Actor a=Actors.current();
        if(("STAFF".equals(a.kind())&&a.userId()<=0)||(!"STAFF".equals(a.kind())&&a.identityId()<=0)) throw new Problem(401,"IDENTITY_REQUIRED","身份失效");
        if(key==null || !key.matches("[A-Za-z0-9_.:-]{8,64}")) throw Problem.bad("Idempotency-Key格式错误");
        String scope="STAFF".equals(a.kind())?"STAFF:"+a.userId():"EXTERNAL:"+a.identityId(), hash=Json.hash(body);
        Map<String,Object> p=P.of("scope",scope,"action",action,"key",key,"hash",hash);
        db.write("INSERT INTO channel_idempotency(scope_key,action_code,idempotency_key,payload_hash,created_at) "
            + "VALUES(#{p.scope},#{p.action},#{p.key},#{p.hash},UTC_TIMESTAMP(3)) ON DUPLICATE KEY UPDATE command_id=command_id",p);
        Map<String,Object> row=db.required("SELECT command_id,payload_hash,result_json FROM channel_idempotency "
            + "WHERE scope_key=#{p.scope} AND action_code=#{p.action} AND idempotency_key=#{p.key} FOR UPDATE",p);
        if(!hash.equals(row.get("payload_hash"))) throw new Problem(409,"IDEMPOTENCY_CONFLICT","相同重试键对应不同内容");
        if(row.get("result_json")!=null) {
            Map<String,Object> result=Json.readMap(row.get("result_json").toString());
            result.put("_replayed",true); return result;
        }
        Map<String,Object> result=work.get();
        db.write("UPDATE channel_idempotency SET http_status=200,result_json=#{p.result} WHERE command_id=#{p.id}",
            P.of("id",row.get("command_id"),"result",Json.write(result)));
        return result;
    }
    public static void version(Map<String,Object> row,Map<String,Object> body) {
        if(Inputs.nonNegative(body,"expectedVersion")!=Inputs.number(row.get("version")))
            throw new Problem(409,"VERSION_CONFLICT","记录已更新，请刷新");
    }
    public static Map<String,Object> payload(long id,Map<String,Object> body) {
        Map<String,Object> p=new LinkedHashMap<>(body); p.put("targetId",Long.toString(id)); return p;
    }
    public static List<Map<String,Object>> rows(Map<String,Object> body,String key) {
        if(!(body.get(key) instanceof List<?> list)||list.isEmpty()||list.size()>5000)
            throw Problem.bad("导入行数必须1..5000");
        List<Map<String,Object>> out=new ArrayList<>();
        for(Object value:list)out.add(Inputs.map(value));
        return out;
    }
}
```

## 4. 成绩统一语义

考试 `edu_exam`（academic_year显式YYYY-YYYY连续两年、semester显式1/2，按学期筛选但不根据日期推断），考试班级 `edu_exam_class`，科目满分 `edu_exam_subject`，原始成绩 `edu_exam_score`，发布快照 `edu_score_release`/`edu_score_snapshot`。导入匹配学号与考试冻结名册，不按姓名；转班不修改考试班级。每科状态 SCORE（decimal(8,2)，包含 0）、ABSENT、EXEMPT、UNRECORDED；后三者分数必须 NULL，不能互相替代。满分必须显式大于 0，不造默认 100。只有所有 `counts_total=1` 的科目都是 SCORE，total_score 与 total_full_score 才非 NULL，否则均 NULL；免考不自动从分母剔除。科目集合为空不得发布。

按“考试+考试当时班级”发布。预览未清错误、缺行/缺科/UNRECORDED、超满分、重复学号科目均不可发布；ABSENT/EXEMPT 是明确确认结果允许发布但总分 NULL。发布新建不可变快照，家长只查当前 PUBLISHED release，WITHDRAWN 立即不可见；更正先撤回、修订草稿，再新建 release_no，老快照仅内部留痕，绝不 UPDATE 快照正文。家长只能看本人每科分数/状态/满分、合计和历史，无排名、等级、评语。

## 5. 导入与审计默认规则

仅 `.xlsx`，10 MiB、最多 5000 数据行、单 sheet、只读静态单元格；拒绝公式、合并区域和隐藏 sheet。服务端按精确列名校验，不执行公式、不按显示文本猜日期。先上传解析、生成服务端暂存行与校验错误；校方查看预览摘要后带 `batchId+expectedVersion+confirmationHash` 提交，不接受客户端传解析后的行替换暂存正文。错误行总数必须为 0，超过约束整批回滚；重复 commit 同键重放，换键已 COMMITTED 返回原业务结果。暂存 24 小时后 EXPIRED 不可提交；包含个人信息的暂存 payload 在 30 日清理，保留摘要、计数、操作人、时间与审计事件。不会自动运行清理脚本。

所有可变新表均有 version 和四个审计字段；动作审计 `edu_parent_audit` 只存 actor_type(STAFF/EXTERNAL)+actor_id(user_id/identity_id)/action/target/idempotency摘要、前后版本与原因编号，无手机号、成绩正文、令牌。日志只存 traceId、动作、目标ID、错误码。FK 均 RESTRICT，拒绝物理删除已有关联的学生、家长、考试。
