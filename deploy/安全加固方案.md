## 零、为什么针对轻量服务器做了调整

腾讯轻量应用服务器和普通 CVM 有三处关键不同，方案已据此调整：

1. **双层防火墙**：轻量服务器有「腾讯云控制台防火墙」+「服务器内部防火墙」两层。改端口/绑定本机后，**控制台那一层也要手动同步**（脚本无法操作控制台）。
2. **服务器已装 ufw**：你的服务器 `ufw status: active`，默认 `deny incoming`。所以脚本用 **ufw** 增量调整，而不是另起 nftables（避免冲突）。
3. **防 DDoS 靠腾讯云**：轻量服务器自带「DDoS 基础防护」（大禹），大流量 DDoS 由腾讯云清洗，**服务器内部做不了也无需做**。脚本只做「防暴力破解 + 连接限速」。

## 三、⚠️ 关键风险（执行前必看）

1. **SSH 白名单自锁风险**：脚本会把 SSH 改为仅 `176.122.189.165` 可访问。**执行前务必确认你当前出口 IP 就是它**（本机跑 `curl ifconfig.me`）。否则执行后 SSH 立即断开，只能通过腾讯云控制台的 VNC 登录恢复。

2. **服务中断**：重启 MySQL/Redis/生产/测试后端，约 1-2 分钟不可用，低峰期做。

3. **Redis 生产/测试共用**：同一实例（db0 生产 + db1 测试），端口一改两个后端都同步（脚本已处理）。

## 六、关于「防 DDoS」的准确说明

- **大流量 DDoS**（SYN flood、UDP flood、反射放大）：由**腾讯云大禹 DDoS 基础防护**自动清洗，你在服务器内部无法也不应自己处理。轻量服务器该防护默认开启，可在控制台查看。
- **应用层攻击**（SSH 暴力破解、CC、慢速攻击、端口扫描）：
  - SSH 暴力破解 → **fail2ban**（本脚本）
  - 连接限速 → **ufw limit**（本脚本）
  - 端口扫描 → 已通过「绑定本机 + 改高位端口 + 白名单」降低暴露面

**结论**：你的诉求「系统增加防 DDoS」已通过「腾讯云基础防护（已有）+ 服务器内 fail2ban/限速（本脚本）+ 减少暴露面」三方面覆盖。若未来业务流量大、需要抗更大 DDoS，需要购买腾讯云「DDoS 高防包」，那是在控制台买服务，不是服务器内配置。

### 关键踩坑记录（重要）

1. **`root@127.0.0.1` 密码是单独一条**：MySQL 的 root 用户有 `localhost` 和 `127.0.0.1` 两个 host 记录，密码互相独立。后端用 `127.0.0.1` 连接时匹配的是 `root@127.0.0.1`，所以**两个都要改密码**，否则后端启动后登录失败。原脚本只改了 `localhost`，已修复为两个都改。

2. **当前出口 IP 与固定 IP 不一致**：执行时实际出口 IP 是 `113.57.10.164`，与脚本里写的固定 IP `176.122.189.165` 不同。**已把两个 IP 都加入白名单**，避免自锁。以后若换了网络环境，需先确认出口 IP（`curl ifconfig.me`）再加白名单，否则会被锁在门外。

3. **Redis 配置文件位置**：`/etc/redis/redis.conf` 存在但属 `redis:redis` 且权限 `640`，普通账号 `ls` 会看到空/denied，需 `sudo` 才能读。脚本里所有 Redis 操作都要走 sudo。

4. **ufw 顺序陷阱**：脚本原先是「先删 OpenSSH 全网放行、再加白名单」，有 SSH 瞬间断连风险。已改为「先加白名单、再删全网」，确保 SSH 永不中断。

5. **后端重启需耐心**：Spring Boot 启动约 40-60 秒，健康检查过早会误判 `000`。需等 `200` 才确认成功。
